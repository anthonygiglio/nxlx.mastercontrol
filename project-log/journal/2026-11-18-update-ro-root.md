## 2026-11-18, J-174: the updater refuses while the read-only root is on

- The problem: with `nxlx-rootfs enable` the whole `/` is a RAM overlay, so an update or a rollback wrote its release, units, `current` and settings backup to RAM and reported "done"; at the next restart the node came back on the old release and nobody was told. Research: nxlx_shared/specs/rootfs-updates_2026-11-18.md, option A.
- mctl/update.py: `require_writable_root()` raises UpdateError with the plain sentence (rootfs.UPDATE_REFUSAL: turn it off with sudo nxlx-rootfs disable, restart, update, then enable and restart). It runs at the start of `Updater.check`, `apply` and `rollback`, and in `main()` before the usb and inbox commands look for or open anything. In the units the refusal comes after the lock and the scratch sweep, and before anything is downloaded, opened or unpacked. The existing handler writes the sentence to the result file as "failed", so the panel's "Last update failed" line shows it. `status` is not refused. There is no override: `--force` is a different thing (version and schema checks) and does not skip it.
- mctl/api.py: `GET /api/system/update` now carries `read_only_root` and `read_only_message`; the upload (before a byte is read, so a 300 MB bundle does not go into RAM) and `POST /api/system/update` answer 409 with the sentence. The state is read with `rootfs.current_state()`, as sysd and boxcare already do.
- mctl/web/app.js, Updates card: the sentence as a warning line, the Upload and Install buttons disabled. No layout change.
- Small fixes: bin/nxlx-convert gave the old command name with an action that does not exist, and now says "sudo nxlx-rootfs disable". DEVICE-TESTING row RA14 expected `/var/lib/nxlx` to be kept under the read-only root; it is not (it is on `/`), so the row now expects the graphic to be gone after the restart, as mctl/README.md says. New rows UR1 to UR5, all NOT RUN (Pi and M710q).
- Tests: tests/test_update.py ReadOnlyRootTest (each refused action under a faked state, nothing changed, unchanged when normal), tests/test_update_button.py (the command line writes "failed" with the sentence for usb, inbox, apply and rollback and opens nothing; the API shows the state and answers 409 to the upload and the start).
- Not proven: that `current_state()` reads the overlay correctly on a real Pi and on the M710q with the overlay on (never turned on on a node), and that the panel and SSH refuse there. Rows UR1 to UR5.
- Review fixes (same PR): the Updates card used an undeclared variable in strict mode (a ReferenceError on every draw); fixed, with browser assertions for a normal and a read-only answer. install/install.sh now refuses too (the same sentence, read from the / line of /proc/mounts; not with --stage or --dry-run), tests/test_rootfs.py pins both overlay forms and a docker mount, and the update tests no longer depend on the host's own /proc/mounts.
