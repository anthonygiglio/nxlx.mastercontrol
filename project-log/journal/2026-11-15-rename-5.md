## 2026-11-15, rename PR 5: the renderer and its names (D135, kind render)

- **Applied:** `python3 tools/rename-apply.py --kind render --write` changed 1,867 places (85 distinct names) in 133 files and renamed two: `render/src/pvj.h` to `render/src/mctl.h`, `tests/test_pvj_render.py` to `tests/test_mctl_render.py`. The program is now `render/mctl-render` (Makefile target, .gitignore, `--version`, log prefix), and every socket command and property it shares with the player moved with it: `mctl-crossfade`, `mctl-fade-to-program`, `mctl-source(s)`, `mctl-shader(s)`, `mctl-graphic(s)`, `mctl-final`, `mctl-screen`, `mctl-capture`, `mctl-heap`, and the `mctl-render` property itself. The shader helpers and the reserved prefix are `mctl_` (`mctl_pos`, `mctl_t` and so on, `MCTL_HP`), program files start `//!MCTL 1`, the mapper's textures are `MCTLWARP*`, and mpv's filter labels are `mctlfliph`, `mctlflipv`, `mctlsound`.
- **Rows added to the table (render):** `pvj-heap` (J-157, after the table was written), the three socket test hooks `pvj-test-blank`, `pvj-test-buffer`, `pvj-test-refuse` (to `mctl-test-*`; the shorter package row `pvj-test-` stays for temp names), `PVJ_VERSION` to `MCTL_VERSION` (a C macro in mctl.h, not an environment variable, so not the env row's NXLX_), and `PVJ_LINE` to `MCTL_LINE` (the line macro in every generated shader; the table had it under the env family). shaders.py's filter of the player's own names in compiler messages now looks for `MCTL_` instead of `PVJ_`.
- **Reverted by hand:** everything under project-log/ (history, PR 10 rewrites it), and `bin/nxlx-convert`, whose rename table must keep the old name `pvj-render` on its left.
- **Fixed by hand:** test method names holding `_pvj_render_` (`tests/test_latescreen.py`, `test_output.py`, `test_player_layers.py`, `test_renderer.py`), which no row reaches by the boundary rule. tests/test_shaders.py: the upper-case reserved name it checks is `MCTL_IN_TIME` now (it was `PVJ_IN_TIME`, the old prefix in capitals). tests/test_sources.py compares the mapper's shaders byte for byte with the release before D101, read from git: that old code is now passed through the table's render rows first, so `PVJWARP` and `MCTLWARP` are not a difference.
- **Kept on purpose (later pull requests):** the environment variables `PVJ_RENDER_TEST` (the tests' opt-in), `PVJ_RENDER_TEST_*` (the hooks' values), `PVJ_RENDER_BIN`, the C define `PVJ_RENDER_TEST_HOOKS` (all kind env, PR 8); the package path `pvj/`, the group `pvj`, `pvj.env` (PR 6, PR 7); `pvj-link`, `pvj-raster` and their units (system, PR 7); the CI job id and name `pvj-render (...)` (required checks, PR 10). Only the steps' display names in the job changed.
- **Callers outside render/:** no unit, script or image file runs the renderer by name. The player starts it (`pvj/renderer.py`, `binary()`: `render/mctl-render` beside the package in the same release), so the player and the program always come from one release and agree on the names. install.sh builds it (`make -C render`, the default target, now `mctl-render`); its messages say mctl-render. The panel's renderer card says "New (mctl-render)". tests/real_convert_test.sh already copies the old program to `render/mctl-render` for its stand-in release.
- **An update from the current release:** install.sh copies a fresh release folder from the source (render/ is source only in a bundle) and builds `mctl-render` there; the player restarts from the new release and starts `mctl-render`. The old `pvj-render` stays only inside the old release folder, which is the rollback target and needs it, and nothing else runs it. install.sh now also removes a `render/pvj-render` that a hand-built source folder would carry into a new release. Program files are written at each load and kept in memory only, so no saved file holds `//!PVJ`. A stored user shader that used a name starting `pvj_` was refused before and is accepted now; one starting `mctl_` is refused now.
- **Test added:** tests/real_install_test.sh, a step that makes a copy of the release with a planted `render/pvj-render` current, plants another in the source folder, updates, and checks that the new release has no `pvj-render`, the old release keeps its own, `previous` points at it, and no file of the new release or unit names `pvj-render`. It runs only in CI's real-install job (root on a throwaway runner).
- **Tests run (WSL Ubuntu, mpv 0.41, llvmpipe):** `make -C render WERROR=1` and `TEST_HOOKS=1` build clean (`mctl-render 0.12.0`). With `PVJ_RENDER_TEST=1`: tests.test_native_shaders 115 OK; tests.test_mctl_render 126, of which 5 pacing tests fail (flips a second under 51, and one source-move count), and the same 5 fail the same way on master d7259ce on this machine, twice each (the software GPU's frame rate here, not the rename; CI is the judge). - **Review fixes (PR 298):**
  - The renderer's readers compared the new prefixes by the old prefixes' lengths, typed by hand: fx.c checked `mctl_` with 4 and `mctl_in_` with 7 (so an input called `mctlSpeed` was refused and `mctl_inX` taken), fx.c looked for `mctl_main` with 8, and hook.c refused `mctl_` with 4 (so a texture called `mctlTable` was refused). They now use `STARTS(s, "prefix")` (mctl.h, the literal's own length) and `sizeof("mctl_main") - 1`. No other string-and-length use of a renamed name is left in render/ or tests/ndi_standin. Tests: `RefusalTest.test_the_players_prefix_is_read_by_its_whole_length` (tests/test_native_shaders.py: `mctl_inlevel`, `mctl_level` and a program without `mctl_main` are refused for the reader's own reason, read from the renderer's log; `mctlSpeed` and `mctl_in_level` are taken and draw) and `MappingTest.test_a_texture_name_is_refused_for_the_players_prefix_only` (tests/test_mctl_render.py). Both fail on a build of the first commit of this branch and pass now.
  - tests/real_install_test.sh failed in CI at its own new step: bin/ is copied into every release, and bin/nxlx-convert names `pvj-render` on purpose (its rename table). The check now reads only what runs or starts the renderer: the package, render/, bin/ without nxlx-convert, and the node's pvj-* units. Its executable bit, lost in the first commit, is back.
  - tests/test_sources.py now loads the release before D101 unchanged and passes only its returned shader text through the table's render rows, so a change the rename made inside the mapper cannot hide on both sides.
  - Outside the repository: the node scripts in nxlx_shared/scripts that named the renderer or its socket commands now find the running renderer by either name (mctl-render first, then pvj-render; with none running, the current release's file) and use the matching names, so they work before and after the deploy. That folder has no git of its own.
- **The guard:** `render` added to `LANDED`; `tools/rename-allow.txt` recounted (the old PHP panel's `pvj_` functions, kept as the upstream original, now count; install.sh and real_install_test.sh are listed for the old name they remove and check).
