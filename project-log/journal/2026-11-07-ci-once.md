## 2026-11-07, CI runs once per pull request commit, and a newer push cancels the older run

- `ci.yml`, `pvj.yml` and `security-tests.yml` ran on every `push` and every `pull_request`, so each commit on a pull request ran the three workflows twice (seen on `presence` at 0247c9c: a `push` and a `pull_request` run of each). With five pull requests open the queue held about 40 waiting runs and a pull request took more than an hour to get its checks.
- `push` now runs on `master` only; pull requests run on `pull_request` alone. A branch pushed with no pull request gets no CI until one is opened.
- Each of the three has `concurrency` by workflow and pull request number (the ref on `master`), with `cancel-in-progress` on pull requests only: a new commit on a pull request cancels the run of the commit it replaces, and runs on `master` are never cancelled mid-way.
- `project-log.yml` already ran this way and is unchanged.
- On `master` GitHub keeps one waiting run per group: when two merges land while a run is going, the waiting run of the first is dropped and the second covers the tip.
