## 2026-11-08, Graphics 1: safe image upload (pvj-raster), slice 1 of D129

- Recorded Anthony's five answers in the design and in D129 first (PR #232, now ready), then built slice 1 on `graphics-raster` (the design merged in).
- `render/raster/pvj-raster.c` is the only code that decodes an upload: libpng, libjpeg and the vendored nanosvg (zlib licence, unchanged, upstream commit 239e102 in THIRD_PARTY_LICENSES.md). One request in, one clean PNG out. PNG, JPEG (orientation applied, CMYK and lossless refused, a cut-off file refused instead of filled with grey) and SVG (refused in words for a script, an entity, an internal DTD, an external href or url(), an embedded picture, a style sheet or text). Long side at most 2048, metadata dropped because the PNG is written from pixels. It opens no file and makes no connection; the test reads the source for that.
- `install/pvj-raster.socket` (Accept=yes, group pvj-raster, 0660) and `pvj-raster@.service` (own account, PrivateNetwork, a syscall filter without the privileged, resource, network, ipc, keyring, chown and setuid groups, no executable memory, 512 MB address space, 10 s CPU, 15 s wall, 256 MB, InaccessiblePaths for the settings and the other services). `install.sh` builds it, makes the account, joins the panel to the group and enables the socket on every board; the image's package list and enable line follow.
- `pvj/raster.py` does the checks that need no decoder (size, magic, extension against magic, PNG and JPEG header sizes, JPEG kind) before anything reaches the helper, and holds the store (names by `valid_name`, always `.png`, no overwrite without `replace`, 64 files, 100 MB, 5 new a minute, links never followed). Routes: `POST /api/graphics/upload`, `GET`/`POST /api/graphics/file`, `GET /api/graphics/thumb`, all Operator and Owner only.
- Checked here: `tests/test_raster.py` (45 tests; the 16 that run the real program need PVJ_RASTER_TEST=1), the role table, units, install, license, run-folder and project-log modules. The program was also run under the unit's properties as a systemd user service (`systemd-run --user`): good PNG and SVG answered, the 40-megapixel one-colour PNG in 0.6 s and 7 MB peak, a file marked inaccessible refused, the system read-only. Not run as the real socket-activated system unit, on a Pi, fuzzed, or reviewed by someone else. The panel's Library > Graphics tab is not built in this slice (see the addendum).
