## 2026-11-14, PC nodes get the VA-API driver for their graphics, and pvj-selftest says whether hardware decoding is there (J-152)

- **Why.** On an Intel PC node (Lenovo M710q, Debian 13, HD 630) mpv decoded in software, without a word, until `intel-media-va-driver` was installed by hand; with it, 4K60 HEVC played with nothing dropped. The installer never installed a VA-API driver, so every PC node had the same trap.
- **What.** `install/install.sh`, on x86_64 only: the display controllers are read from sysfs (`/sys/bus/pci/devices/*`, class 0x03); Intel (vendor 8086) gets `intel-media-va-driver`, AMD (1002) gets `mesa-va-drivers`, and either gets `vainfo` too, a small tool so a person can see what the driver decodes. Best effort, like the other optional packages: a failed install is said ("the install goes on, and mpv decodes in software") and the install goes on. `--offline`, stage mode and a system without apt only say what is missing; `--dry-run` prints the apt command. The installer says which graphics it found on every PC install. A Pi gets none of this. In stage mode only, `PVJ_INSTALL_ARCH` and `PVJ_INSTALL_PCI` stand in for the machine and sysfs, for the tests.
- **Self-test.** `pvj-selftest` reports `hardware_decoding` (from `hardware.va_decoding`): the render nodes, the vendors of the graphics, the VA-API driver files, `available` and a plain line, with the package to install when the driver for the graphics is missing. It is information, not a check, so a node without it still passes; a Pi says "not checked".
- **Choices.** sysfs and not lspci: sysfs is always there, lspci (pciutils) often is not, and one way is simpler to test. Only `intel-media-va-driver` for Intel: it covers Broadwell (2014) and newer; an older Intel graphics would need `i965-va-driver`, left out until such a node turns up (the self-test would say there is no driver for it). NVIDIA is left out: its VA-API path is another driver stack, and no node has one.
- **Checked.** `tests.test_install` (33, five new: Intel, AMD, both, other graphics and a Pi, offline and dry run, the best-effort line), `tests.test_hardware` (17, six new), `tests.test_player -k selftest`. Not run on the M710q or any real PC node, and not run as a real (non-stage) install: deploying waits for the end of the show freeze.
