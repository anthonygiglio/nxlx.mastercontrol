## 2026-11-18, cache of the downloaded apt packages (J-173)

- The runners' mirror was slow all afternoon and jobs failed with "ci-apt: gave up after 3 attempts" before any test. tools/ci-apt.sh now takes an optional CI_APT_CACHE folder: its .deb files are copied into apt's cache before the install, and after a successful install apt's cache (after apt-get autoclean) is copied back. A new composite action, .github/actions/apt-cache, sets CI_APT_CACHE and runs actions/cache@v4 on it (key: apt, runner OS, job, hash of the job's package list, runner image; restore-keys fall back to the same package list on another image, then to the job). It is used by unit, shaders-gpu, effects-gpu, real-convert, real-install, panel-ui and the Ubuntu leg of the renderer job. apt still runs update and checks each cached file against the lists, so a deb of another version is ignored and fetched. A cold cache behaves as before. Not done: installing from the cache when update itself times out. Only a CI run shows the hit rate.
- Review of PR 306 (J-173), changes: the cache is now restored with actions/cache/restore and saved by a second action, apt-cache-save, as the last step of each job with if: always(), so it also runs when ci-apt.sh gave up (a failed step does not skip an always() step). Save key is the base plus run id and attempt; restore-keys fall back to the base, to the package hash on any image, then to any apt cache of the runner OS; the job name is no longer in the key. ci-apt.sh adds the complete debs to the cache on a give-up (archives/partial is never copied). apt checks a cached deb by size only, so before a retry the restored debs dpkg-deb cannot read are removed from apt cache, and before the last attempt all of them.
- Second review of PR 306: a damaged restored deb is now also removed from the saved folder (plain cp, not cp -u, since downloaded debs carry the server old date); the drop of all restored debs before the last attempt is gone and the check before each retry is stricter (dpkg-deb --info and --fsys-tarfile); ci-apt.sh makes the file named by CI_APT_ADDED when a deb is new to the saved folder or one was dropped, and apt-cache-save saves only then (still with always(), so a failed job that added something saves too); key.sh and both actions take the packages through env.
