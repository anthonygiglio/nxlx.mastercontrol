## 2026-11-15, three flaky steps in the panel and strobe tests (J-019)

- Both were named in the 2026-11-14 note on the waits: the run died at a "Route is already handled" unhandled rejection near lines 480 and 2564 of tests/ui/panel.test.js, and at the strobe `steady` check with the clip at 0.36 s. All three fixes are in test code.
- Route already handled: a handler that awaits route.fetch() and then calls route.fulfill() is in flight for a few milliseconds per request. When page.unroute() took the last route off in that time, Playwright switched the interception off, the browser carried the request on by itself, and the fulfill that came after it threw. The status routes (the panel asks every second) were the ones hit. Playwright's unroute(url, handler) has no wait option here (only unrouteAll takes a behavior), so tests/ui/routes.js changes page.route and page.unroute: a route being taken off first stops taking new requests (they go on unchanged, as they would after the take-off), then waits for the calls it has in flight (up to 5 s), then comes off. panel.test.js calls patchUnroute once after the browser starts. A handler that really answers twice still fails.
- Strobe `steady`: the press waited for three looks in a row, 100 ms apart, inside a window of 0.3 to 0.8 s of a 2 s pass. Under load a look takes long enough that three never fit, and the wait ran out after 20 s. It now waits for one look inside 0.3 to 0.7 s, taken without the pause; that the clip is rolling and has a picture is still proved by the three looks before it.
- A third came out of the full Python run (three parts at once): tests.test_strobe.MidiHubTest.test_the_lease_alone_ends_it_if_nothing_renews_it_and_nothing_releases_it failed. The hub notes a held strobe control only after the hold has gone through (MidiHub._strobe_note), and the test cleared that note as soon as the effect was on, so the clear could come first, the note was made after it, and the hub's beat went on renewing the lease. The test now waits for the note before it clears it.
- Numbers (WSL, 24 busy loops on 16 cores, each run bounded):
  - Route take-off, 40 ms handler, 40 take-offs a run: 86 errors in one run before; 0 errors in 20 runs (800 take-offs) after.
  - Press wait, 20 tries under load: 0 passed and 20 failed before; 20 passed and 0 failed after (3.0 to 3.3 s each).
  - The lease test alone, in a loop: 2 failures in 130 runs before; 0 in 150 after.
- Whole suites on this rig: the panel test passed (the first run stopped once at the NDI scope card, `e.closest('.card')` null at line 1885, and passed on the second; not touched by this change). The Python suite in three parts: no failures but tests.test_release (git clone --local across devices is refused here), tests.test_rootfs.test_enable_refused_when_media_lives_on_root (this rig's media is on the root file system) and the lease test above, which is fixed.
