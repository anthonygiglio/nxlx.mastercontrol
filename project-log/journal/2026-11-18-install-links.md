## 2026-11-18, J-175: the installer never follows a link in /var/lib/nxlx

- The problem: /var/lib/nxlx belongs to the panel account (nxlx-web). install.sh, as root, ran `chown nxlx-web:nxlx-svc /var/lib/nxlx/settings.json*` and chowned and chmodded the media folder (default /var/lib/nxlx/video) by path, so a link planted there made the next install or update give the link's target (a file in /etc, say) to the panel account.
- install/install.sh (first version checked for a link and then used the path; the review showed the panel account can swap a name for a link in that gap, 86 of 300 tries, because /var/lib/nxlx has no sticky bit): nothing under /var/lib/nxlx is changed by path any more. `nxlx_fd_own PATH BASE USER GROUP MODE` (python3, already required) walks the path from /var/lib/nxlx one name at a time with O_NOFOLLOW|O_DIRECTORY, makes a missing folder with mkdir on the open folder, and does fchown and fchmod on the folder it holds, so a link at any name fails the open and the install stops with a message. Used for backups and for the media folder when it is inside /var/lib/nxlx; a link at those final names is removed first (as PR 308 did). settings.json* is `find -maxdepth 1 -type f -links 1 -exec chown -h`: links and files with a second hard link are skipped. The media folder is normalised like the prefix (no trailing slash, no //) before the inside-/var/lib/nxlx test. A media folder elsewhere is the owner's choice and a link there is followed as before. Audit: no other chown, chmod or chgrp in install/ touches a path under /var/lib/nxlx.
- Tests: tests/test_install.py StateFolderLinksTest cuts the functions out of install.sh. The helper runs for real as the current user against real links (final name, middle of a path), checks the target's owner and mode are unchanged, that folders are made and 2775 then 0700 set, and that the setgid bit is cleared; the state and media functions run on a temp folder with chown and chmod recorded; the trailing-slash and double-slash spellings are covered. tests/real_install_test.sh has a new step: links at settings.json.bak (to a root-owned 0640 file with content), backups and video (to a root-owned 0755 folder), then a reinstall, then the targets unchanged and backups and video real folders.
- Not proven: the real install test step was not run (it needs a disposable machine); the fd helper was not run as root, so fchown to another account is only exercised on the test user's own account. Other writers (nxlx-sysd and so on) are out of scope and carded separately.
- Last round: a removed link at the media folder is announced with where it pointed, that the clips are untouched, and to use --media; install/README.md says the same. --media /var/lib/nxlx itself is refused. The stop messages no longer blame a link for every failure. The real install test checks video is the player account's nxlx-svc 2775 folder after the planted-link step (not run).
