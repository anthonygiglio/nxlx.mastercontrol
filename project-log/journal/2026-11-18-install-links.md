## 2026-11-18, J-175: the installer never follows a link in /var/lib/nxlx

- The problem: /var/lib/nxlx belongs to the panel account (nxlx-web). install.sh, as root, ran `chown nxlx-web:nxlx-svc /var/lib/nxlx/settings.json*` and chowned and chmodded the media folder (default /var/lib/nxlx/video) by path, so a link planted there made the next install or update give the link's target (a file in /etc, say) to the panel account.
- install/install.sh: the block is now two functions. `nxlx_state_fix`: every chown uses -h; settings.json* is handled by `find -maxdepth 1 -type f -exec chown -h`, so a link is skipped (left as planted, unused); a link at backups is removed as in PR 308, and chown and chmod of backups run only if it is not a link. `nxlx_media_fix`: a link at a media folder inside /var/lib/nxlx is skipped with a log line; a link the owner chose with --media elsewhere is followed as before. Audit: no other chown, chmod or chgrp in install/ touches a path under /var/lib/nxlx.
- Tests: tests/test_install.py StateFolderLinksTest cuts both functions out of install.sh, runs them on a temp folder with chown and chmod replaced by recorders, and checks that planted links (settings.json.bak, settings.json.tmp, backups, video) never reach chown or chmod and the target keeps owner and mode, and that every chown carries -h. tests/real_install_test.sh has a new step (plants a link at settings.json.bak and at backups pointing at a root-owned 0640 file, reinstalls, checks the file is unchanged and backups is a root 0700 folder).
- Not proven: the real install test step was not run (it needs a disposable machine). A swap between the not-a-link check and the chmod of backups is not closed (chmod has no -h); the modes set there are only 0700 and 2750, and the owner changes cannot follow a link.
