## 2026-11-10, slice 4d review fixes (D132)

- deny.json is read with a limit of 256 KiB and written to fit in it (compact JSON; tombstones give way first, a peer flood's before the Owner's). A file that is there but cannot be used is kept aside as `deny.json.unreadable`, logged and shown as `deny_problem` on the Owner's status; it is never taken for no file. A test fills the worst case (256 rows with the longest names, 256 tombstones, over 64 KiB) and reloads with nothing lost.
- Epochs: a peer's deny up to 10^9 - 2, tombstones at most 10^9 - 1, removals made here at most 10^9; a stored epoch out of range is clamped and logged, not set to 1. Tested at both ends and across a restart.
- A renewal sets `by` and the peer mark from the renewing node, counts toward the peer share of the file and is in the banner. Tombstone eviction takes a flood's first. Pushes owed are pruned to approved nodes; a push that met a running call is tried at the next tick. The removal number comes from a counter kept in the file. Design section 22 says a carried Owner from a carry-full node can use these routes here.

## 2026-11-10, node handover slice 4d: remove a node from this cluster, and Allow again (D132)

- The Owner's action, as API routes (the panel is slice 5): `POST /api/fleet/remove {"id"}` puts a node of the approved set on the deny list, drops its fingerprint acceptance, signs out every device it carried on this node (the existing sweep, so it is at once and before any network), writes the event with the count, and starts the push. `POST /api/fleet/allow {"n", "epoch", "typed"}` allows one removed node again on this node only; `POST /api/fleet/allow/by {"by"}` lifts everything one peer sent (the way back from a node that denied the others). All three are the Owner's, over the secure connection, never through the support tunnel, and have `fleet` in the path, so the 4c by-name test holds them to the Owner. They are not on the peer port.
- Deny rows have an integer epoch. Allow again removes the row and keeps a local tombstone of epoch + 1 in `deny.json`; a tombstone is never sent. A deny from a peer is taken only above this node's row or tombstone, a higher epoch renews a row, equal or lower changes nothing and is no flood. The digest now covers (key, epoch). A new removal on this node after an Allow again is made at tombstone + 1, so it beats the old denies still going round. The Allow again request carries the epoch the Owner saw, so a copy of an old request cannot undo a newer deny (409), and the fingerprint is typed back.
- Spreading is a push as well as the pull of slice 3: a hello can carry up to 24 removals (key, name, epoch). One background pusher at a time, a failure charged to its target only (`budget=False`), never the node-wide outbound count; the receiver reads pushes with an allowance of its own per caller key (12 a minute), and the call is still answered when it is used up. A node that takes a removal passes it on to its own approved peers; a node that could not be reached is owed the push and tried again after 5 minutes by the lease worker. A node that was off catches up on its next hello to anybody (the digest differs, the answer carries the removals).
- Owner's status: each removal has `n`, `epoch`, `from_peer`; `banner` lists peers that sent removals lately, red when one peer sent more than one in a minute. No key or fingerprint of another node is in any answer (the walk of 4a still passes).
- Not done: the `clear` field of a signed list, `boxcert.py fleet clear`, and dropping a deny when a newer list leaves the node out. The owner asked for the Allow again route instead of re-signing, and the deny list only grows except through Allow again. Left for a later slice or the owner's call. The removed node is not told (it is no longer approved, so every call to it is refused); it learns of its own removal only if an approved peer lists its key in an answer, and then only the status line says so, as in slice 3.
- Tests: `tests/test_cluster_remove.py` (three real nodes and the real peer listeners, plus the routes on the real secure listener). Not deployed.
