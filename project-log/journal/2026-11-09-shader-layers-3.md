## 2026-11-09, shader transitions slice 3: shader pads fade (panel), and the build no longer holds the layers

- Built slice 3 of design/shader-transitions_2026-11-08.md (D130), on pvj-render 0.10.0 plus one fix to its C. On the New renderer (Player.fades_native) a shader chosen by hand or by a pad now takes the Mix transition from a clip or from another shader, and a clip after a shader takes it from the shader, with no still and no blank clip under the shader. Classic mpv, the Pi 3, a renderer from before 0.10.0 and a live input keep the cut and D71's still. Vibes keeps its dip (after slice 4 and a soak).
- Renderer fix (the medium finding of the slice 2 review): `pvj-fade-to-program` held `layer_lock` across the build (up to 3 s), so a Stop, a load, a step in a list, a level or a crossfade from another client waited behind it and the player's 2 s timeout raised while the renderer went on. Now the lock is let go while the render thread builds. `building` (under `layer_lock`) names the layer; `end_fade`, which every command that changes what the front plays calls, also ends the build (asks the program off); the fade command, taking the lock again, finds `building` gone, re-checks and answers "the layer was ended before the load took effect". A level and a get do not end the build. `fx_lock` is still held, so loads go one at a time. Shown on the old C first: the new Stop test fails there with "no reply from mpv", and passes now.
- Player: `fade_to_program` takes `standin`, touches the lists (it had skipped lists.touch), and after a lost answer asks the renderer which program source 1 holds: if it is the one asked for the fade is recorded, if not (or no word) `_native_loaded[0]` is cleared so the next push loads this side's source again. `play_source` on the New renderer loads the program into the front layer and stops the clip, with no carrier. `path_now()` and `status()["path"]` give the shader engine's carrier name as a stand-in for `path` while a program is the picture and its layer is idle, so Engine.on_screen, Vibes, the status and the effect's size read as before. `native_values` answers False, not an error, for the refused set to slot 0 during a shader to clip fade. `Player.shaders_fade()` (no question asked) feeds `mix.shader_cut`, the Mix card's line on a node that cuts.
- Engine/Api: `Api._shader_fade()` (seconds, style, or None), `Engine._fade_for`, `Engine._take_screen`, `FadeRefused`; a refusal in a fade is shown with the GPU's words and "The shader before it stays on." or "The picture before it stays on." (the screen unchanged). `Api._layered_fade` is true for anything `fades_native()` allows. The effects picture check reads a stand-in RGB picture when libmpv has no video-params (no clip under the shader).
