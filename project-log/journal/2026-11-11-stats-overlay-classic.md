## 2026-11-11, the stats overlay on classic mpv (D133 follow-up)

- Found on node-02 why the overlay showed nothing on classic mpv: mpv removes an `osd-overlay` when the connection that created it closes, and `Ipc` opens a connection for each request. The OSD level was not the cause (tried 0 to 3; levels 2 and 3 only add mpv's own time and status text, which must not appear, so the player's `--osd-level=0` is unchanged). Details in the lesson of the same day.
- Fix: `Ipc.hold()` and `HeldIpc` (a connection kept open, answers matched by request id, events passed over); the overlay is drawn, hidden (PIN, blackout) and removed through one held connection, replaced once at once if it breaks, and closed when the overlay goes off, which takes the text off on classic mpv. The start-up clear, the capability probe and the sampler's reads still use single requests. On pvj-render nothing changes for the screen; its removal is still sent directly when no connection is open.
- Tests: the fake player now follows mpv's rule (a one-request overlay is gone at once on classic), tests for one connection kept for the whole run, replacement of a broken one, hiding for a PIN, pvj-render with no connection, and `HeldIpc` against a socket. Run on node-02 by copying this branch's `pvj` folder to /tmp there and driving its own player socket with `av://lavfi` black video: the text was in the screenshot in the bottom right corner, gone while a PIN was pretended, back after, and gone when turned off (the pixel counts are in the PR). The test files on the node were left in /tmp.
- Not done: nothing deployed from this branch; the real panel route on node-02 was not exercised; a capture of the HDMI output was not taken (the coordinator does that).
