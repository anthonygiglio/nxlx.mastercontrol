## 2026-11-09, Node hand-over slice 2: a node keeps the fleet list and knows who is approved

- **Why.** D132, slice 2: the node side of the fleet list, before any node talks to another. Storage, the card, the Owner's routes, the switch and the one question the later slices ask. Nothing is deployed and no node calls another.
- **What.** `pvj/handover.py`: the signed list stored beside `tls/` (checked against the pinned root, this node's fleet, a serial that only goes up, and the list must name this node with its current key), acceptance of one node by a fingerprint typed back, the deny file (storage), the switch `fleet.accept` (off, Owner only, in the box-own `fleet` section), and `approved(id, key)` with `carried_role`. `GET /api/fleet/card` (second route in `policy.NO_GATE`, TLS only, no secret), and under `/api/fleet` the Owner's routes (status, list, accepted, accepted/remove, accept), over https only and never through a support session. New event kind `handover`. A factory reset removes the files. The discovery switch no longer overwrites the other keys of the `fleet` section.
