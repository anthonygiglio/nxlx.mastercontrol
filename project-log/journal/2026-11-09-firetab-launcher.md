## 2026-11-09, The FireTab controller and its launcher, written down

This records work done from 2026-11-06 to 2026-11-09 and not logged until now. The launcher lives in its own local git repo, `C:\Users\antho\nxlx.systems\nxlx-fire-launcher` (no remote); none of its code is in this repo. This entry is the project's memory of it. The trust model is D131.

- **What it is, and why.** The FireTab is a Fire 7 tablet (KFMUWI, Fire OS 7.3.3.1, Android 9, 600x1024), connected to the HP by USB. The owner, 2026-11-09: it "is proof-of-concept for a dedicated controller using recycled tablets and other devices", and it should be brought "up to our high standards". The app is a custom home launcher, "NXLX Panel" (package systems.nxlx.launcher). It shows one node's web panel full screen and nothing else; Back never exits; the screen stays on. Styled with NXLX Signal; Archivo is bundled (SIL Open Font License, licence text in the repo).
- **Versions.**
  - 2026-11-06 (version 1, commits ddaad26 to 1af9971, built in a separate Fire tablet exploration session): a single-node kiosk at node-01's address, source, build and debloat scripts, a no-sudo toolchain, and the home guard service.
  - 2026-11-07 (3234555): the immersive policy.
  - 2.0 (2026-11-09, 2af8a6a, then review fixes in 74cd4f6): node switching, the owner's root as the only trust, the Signal drawer, controller basics (screen on, battery and charger warning in plain words, automatic reconnect, version line), unit tests (`scripts/test.sh`). An independent review ran and every finding was fixed. Medium: a certificate error on a subresource replaced the panel, POST and iframe requests could get past the node-only rule, and the wrong-clock case. Low: system trust, an IPv4-mapped SAN, nxlx-* links from node pages, pop-ups, README errors, the activity lifecycle and tests. Trust went from .local names plus a certificate check for private addresses to the owner's root only (D131). 149 unit tests.
  - 2.1 build 3 (d7811fb, 3095d17; built and installed together as one install): the WebView user agent ends with " NXLXLauncher/<version>" (no JavaScript bridge), and the bottom-edge swipe moved into the root layout, because the old 28 dp strip view swallowed taps on the panel's strip, Blackout among them.
  - 2.1 build 4 (1ab0e07, 176 unit tests): the top-left corner long press is detected in the root layout, so no view lies over the panel. The bottom-edge swipe is also decided in the root layout (`onInterceptTouchEvent`): it starts in the bottom 28 dp, travels up at least 24 dp and mostly vertically; any tap or sideways drag is the page's. The corner hold asks "Open the launcher tools?" first.
- **Trust.** Only the owner's root CA; node addresses only (`.local` names or private LAN addresses, over https); a request that is not to a node gets an empty 403. Full rules in D131. Note: `.local` names do not resolve on this Fire OS, so the tablet reaches nodes by number address; the launcher accepts `.local` anyway.
- **Node switching.** `window.open`, `target=_blank` and a link to another node switch the launcher to that node in place (this makes the panel's Open button on the Nodes list work). It remembers nodes (address, name, which is home) in the app's preferences; version 1's single address is carried over. Each node keeps its own pairing, because WebView storage is per origin. The same box reached by two addresses (a number and a `.local` name) is two origins and needs two pairings.
- **The drawer** (swipe up from the bottom edge, or hold the top-left corner): status (node, network, battery), the node list with Open, Rename, Make home and Forget, Add a node, tools (including Exit to stock launcher), brightness, and the version. Touch targets are 56 dp; forms and questions are sheets, not system dialogs.
- **Fire OS workarounds.**
  - `set-home-activity` reports success but HOME still resolves to Amazon's launcher, which is protected and cannot be disabled. So the app ships an accessibility service, "NXLX home guard" (HomeGuard). It only reacts to window changes of com.amazon.firelauncher, brings the panel forward (debounced), reads no screen content and logs nothing. Cost: after Home the panel returns in about 5 seconds, because Android 9 holds background activity starts briefly after Home. Exit to stock launcher in the drawer pauses it.
  - `settings put global policy_control immersive.full=systems.nxlx.launcher` hides the bars for this app only (Android 9; gone in Android 11). It does nothing if policy_control already holds another value.
  - Many Amazon packages (metrics, logging, OTA) are protected and cannot be disabled without root; the scripts change no network settings. Fire OS updates may re-enable packages and restore Amazon's launcher, so rerun the scripts after one.
  - `scripts/restore.ps1` undoes it all; nothing is removed with `pm uninstall` except the app itself.
- **The signing keystore.** `nxlx-launcher.keystore` is the app's identity; `adb install -r` only replaces an app signed with the same key, and then keeps the accessibility setting and the stored pairings. It is gitignored. A backup is at `C:\Users\antho\nxlx.systems\nxlx_shared\backups\nxlx-fire-launcher\nxlx-launcher.keystore` (the build script shows its passwords; treat it as private). Lose it and a rebuild means uninstalling the app and pairing every node again on every tablet. Back it up whenever it changes.
- **Adding a recycled tablet** (the launcher README, nine steps): turn on Developer Options and USB debugging, check `adb devices`, join the nodes' Wi-Fi, run `scripts\set-home.ps1 -Serial <serial>` (installs, sets home, enables HomeGuard, hides the bars), open the panel app, add the home node by number address if it is not the default, pair each node (the owner does this), optionally run `scripts\debloat.ps1 -DryRun` and review, then check that Home returns to the panel and the drawer shows battery OK. Keep the tablet plugged in.
- **How it relates to the web panel.**
  - The panel looks for `NXLXLauncher/` in the user agent; the root then has `data-launcher`.
  - The panel's This node sheet (2026-11-09-panel-sheet, then 2026-11-09-nodes-sheet) first opened with a swipe up as well, off inside the launcher so one swipe never opened two drawers. The owner then had the swipe taken out of the panel altogether: the sheet opens from Nodes and the pill in the title bar. The swipe up from the bottom edge is the launcher's alone. Inside the launcher the panel's strip still keeps 28 px clear at the foot, where the launcher's swipe strip lies.
  - The panel uses no confirm(), prompt() or alert(); the launcher cancels confirm and prompt, so keep it that way or change the launcher first.
  - The node's Now screen shows this device as "FireTab" (2026-11-07-now-presence).
- **The owner's feedback.** 2026-11-09: "I REALLY like the launcher (NXLX Panel 2.0 (build 2)) on the firetab", especially "being able to swipe up from the bottom of the screen and seeing info like status, device details, nodes, tools, etc." The launcher's drawer and gesture stay. The panel session then built a matching sheet for the web panel at his "yes build the sheet". Later the same day, after trying it on his phone: "I do not like the swipe up panel. Make the new swipe up panel what appears when a user clicks on the node selector at the top", and "The panel that opens when swiping up on the firetab is something different". So the two are different things: the launcher's drawer (the tablet: its nodes, battery, brightness, launcher tools) keeps the swipe up from the bottom edge, and the web panel's This node sheet opens from the title bar, with no swipe (2026-11-09-nodes-sheet).
- **Verified.** Unit tests pass (`scripts/test.sh`: plain Java, a throwaway PKI; with `NXLX_CA_DIR` set it also checks the real node certificates). On the real tablet: install, HomeGuard bringing the panel back, the immersive policy, the panel loading from a node by number address, node switching, the router's own https page refused with the certificate page, and `adb install -r` keeping the setting and pairings.
- **A mishap while testing.** A stray text-selection toolbar opened Amazon's "Register Your Fire" dialog; it was cancelled and nothing was registered.
- **Not yet proven.** None of these has been provoked on the device: the Wi-Fi drop and reconnect, the retry when the clock is wrong, and the subresource and POST 403 blocks. Package names in the debloat list come from public lists, not a live check of every one; the OTA package names are unverified; Fire OS may ignore set-home-activity (then press Home and choose NXLX Panel with Always).
