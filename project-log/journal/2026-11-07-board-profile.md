## 2026-11-07, One profile table by tier

- `pvj/profile.py` is now the one place that says what a tier (lean, standard, full, unknown) is asked to do. It replaces `SMALL_BOARDS`, `SOURCE_CAP`, `SOURCE_DEFAULT` and `SOURCES_OTHER` in `renderer.py` (the detail, `--fast`, `--skip-deblock`, final Automatic and overload-warning rules and `api.py`'s warning check), the board keys of `effects.AUTO` (rows by tier, `AUTO` by kind built from them), and `shaders.heights_for` and `default_height`.
- Kept by exact kind on purpose, each with a comment: `shaderlive.AUTO_BOARDS` (per-shader heights measured on a Pi 4 only), `probe.advice` (what was measured on a Pi 4, not tested on a Pi 3, or a fact of the Pi 5 chip), `modules` (a manifest names kinds, and an arm-other board counts as a pi4 there), and `hardware.playback_profile` (classic mpv's cheap scalers, not part of this table).
- First commit (the table) changes no value. `tests/test_profile.py` compares, for pi3, pi4, pi5, x86, pi-other and arm-other, `command()` argv over 36 settings, the sources default and cap for 7 choices, `detail_arg`, `final_arg`, the overload warning, the effects Automatic lines, Effect detail's default, shader heights and default, the classic mpv arguments and the probe's advice, against `tests/frozen_master_profile.json`. That file was written by running master's own functions before the table existed.
- Second commit, D122: the unknown tier (pi-other, arm-other) takes the lean values for the renderer: Automatic detail 540, `--fast`, `--skip-deblock`, Automatic final pass allowed, 2 sources by default and at most, and the overload warning. Why: those boards were getting the heavy path (the screen's own size, no cheap scalers, 4 sources, up to 8, no warning) while effects.AUTO, the shader heights and the shader default already treated them as a Pi 3; the tables now agree, and a board nobody measured should start careful. The test now expects the lean values for those two kinds in the renderer and master's values everywhere else. Classic mpv's arguments (`hardware.playback_profile`), probe advice, and modules are unchanged.
- Third commit: the player's report (`/run/pvj/player/renderer.json`) now holds `profile`: the tier, the exact model and each value with its reason (`profile.describe`), read back through `clean_report` as data from a less trusted account (tier from the list, short plain sentences, at most 16 rows). `GET /api/renderer` carries the same from the board the panel read, and the Renderer card in `pvj/web/app.js` shows "Settings for this node: <tier> (<model>)" with the list under it. That card is the only panel change; the Panel design brief chat owns the rest of `pvj/web`.
