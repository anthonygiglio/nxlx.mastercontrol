## 2026-11-14, A node without time sync gets systemd-timesyncd, and pvj-selftest says whether the clock is synchronised (J-154)

- **Why.** A plain Debian install on a PC node (Lenovo M710q, node-03) has no time sync at all: its clock was 5 hours slow and `timedatectl` said "NTP service: n/a". Raspberry Pi OS ships systemd-timesyncd, so the Pi nodes never showed it.
- **What.** `install/install.sh`, just after the VA-API block: when none of systemd-timesyncd, chronyd or ntpd (ntp, ntpsec, openntpd) is found under the install root, `systemd-timesyncd` is installed, then `systemctl enable --now systemd-timesyncd.service` and `timedatectl set-ntp true` when systemd runs. Best effort: a failed install, start or set-ntp is said and the install goes on. A system that already has one (a Pi image) is left as it is, and the installer says which one it found. `--offline`, stage mode and a system without apt install nothing and only say it; `--dry-run` prints the commands.
- **Self-test.** `pvj-selftest` reports `clock` (from `selftest.clock_sync`): `synchronized` True, False or None, where the answer came from, and a plain line. `timedatectl show -p NTPSynchronized --value` is asked first; without an answer, `/run/systemd/timesync/synchronized` says yes and its absence cannot tell. Information only, never a failed check.
- **Choices.** The programs are looked for under the install root, not with `command -v`, so stage mode (tests, image builds) looks at the staged system and needs no stand-in. Any board, not only x86_64: the rule is "none there", and a Pi image always has one. A time sync that is installed but turned off is left alone: that may be someone's choice.
- **Checked.** `tests.test_install` and `tests.test_hardware` (56 together, three new installer tests and three new self-test tests), `tests.test_player -k selftest`. Not run as a real (non-stage) install and not on any node: deploying waits for the end of the show freeze.
