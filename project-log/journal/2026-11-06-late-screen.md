## 2026-11-06, a screen that comes after the player starts brings back pvj-render

- Seen on the test node: it booted with no screen, pvj-render exited 2 ("no screen is connected"), the player fell back to classic mpv (D95), and 80 minutes later, with a screen connected and `renderer.json` saying new, it was still on classic. At a show the Pi boots before the projector warms up, so this is the normal order.
- New `pvj/latescreen.py`. When the fallback is "pvj-render did not start (exit ...)" and no screen is connected, the player starts a small detached watcher before it becomes mpv. It reads the connector status files through `hardware.drm_connectors` (every card and connector, none named in the code), and when a screen has stayed connected for 3 s it ends the player's process with SIGTERM; `Restart=always` starts the service by its normal path, so the mode is chosen as at any start and pvj-render is tried again under the same gate (D105: a pvj-render that fails to start or ends twice stays on classic).
- Bounded by a growing wait, with no total: after a switch the next waits 30 s, then 60 s, 120 s, and 300 s from the fourth on, counted from the previous switch. The first switch of a boot has no wait: it comes within a few seconds of the screen settling. The switch times are kept in `late-screen.json`, keyed by boot id, in a folder that survives any restart of the service: the player account cannot write /var/lib/pvj (the panel's 2750 folder), so the unit gets `StateDirectory=pvj-player` (`/var/lib/pvj-player`, mode 0750, made by systemd and owned by the unit's User; it is also the player account's home on an install by install.sh) and `paths.player_state_dir()` names it (env `PVJ_PLAYER_STATE_DIR`). A switch more than 10 minutes old no longer counts (pvj-render has drawn since), so the waits start again at 30 s. A no-screen fallback is not a crash, so a loose cable only makes the box wait longer and never leaves it on classic for the rest of the boot (the first version stopped after 4). `RuntimeDirectoryPreserve` is not used. The watcher writes the file when it starts; only if that fails (an older unit file without the folder, a full disk) does it log that once and keep a floor of 30 s after its own start, so a count that cannot be kept never allows a quick loop. Each switch is logged in plain words.
- Not watched: a crash fallback ("ended twice in a row", "did not answer", "not built"), a screen present at start, a board whose /sys lists no connector, classic chosen, and a player not run by systemd (no INVOCATION_ID).
- Tests in `tests/test_latescreen.py` with a fake /sys tree and a fake clock: a late screen switches once within a few seconds, a flapping cable over an hour gives gaps of 30, 60, 120 and then 300 s and never stops, the wait resets after 10 quiet minutes, the first switch comes within the settle plus 2 s, a count that cannot be written gives the 30 s floor and says so once, a crash stays on classic, a screen present at start changes nothing. Device rows LS1 to LS6 in `tools/DEVICE-TESTING.md`. Not run on a node: nothing here has seen a real projector or a real SIGTERM of mpv by its own watcher.
