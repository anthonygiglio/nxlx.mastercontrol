## 2026-11-15, release 0.1.1 so a node keeps a previous release to roll back to

- Raised the release version from 0.1.0 to 0.1.1. The one source is `__version__` in `pvj/__init__.py`; install.sh and tools/make-release.sh read it from there, and the updater reads it from the bundle. The module files in `pvj/modules.d/*.json` carry their own module versions and were left at 0.1.0.
- Why: install.sh installs to `releases/$VERSION`. The same version again moves the old folder aside and swaps the new one in, so deploying 0.1.0 over 0.1.0 replaced `/opt/pvj/releases/0.1.0` in place and left nothing to roll back to. A different version creates `releases/0.1.1`, repoints `current`, and writes the old `current` target into `/opt/pvj/previous`, so 0.1.0 stays as the previous release.
- Not tested on a node (none touched). Tests that name the version use their own fixture versions; none pins 0.1.0 as the package's version.
