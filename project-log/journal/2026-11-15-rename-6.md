## 2026-11-15, rename PR 6: the Python package pvj to mctl (J-141)

- Moved `pvj/` to `mctl/` (253 files, git sees them as renames) with tools/rename-apply.py (kind package, now in LANDED): imports in code and tests, the bin/ entry scripts, REUSE.toml, install.sh (`cp -a "$SRC/mctl"`, the version read from `mctl/__init__.py`), the units' `--fonts @PVJ_DIR@/mctl/fonts`, the CI paths (ci.yml compile and shellcheck filters, image.yml), the links in docs, README files and tools. The rows added to the table by hand: `pvj-autocert` (thread name and user agent of the certificate client). Project-log files were not rewritten (old entries are not changed); their old names are in the allow list.
- Not in this PR, kept as they are: units, accounts, the group pvj, /opt/pvj, /var/lib/pvj, /etc/pvj, /run/pvj, bin command names (pvj-player and so on), PVJ_* variables, bundle names, pvj-update and pvj-recover, the image stage folder, CI job and workflow names, `@PVJ_DIR@`. They are PR 7, 8 and 10.
- Old layout for one release: `update.inspect_bundle` takes a bundle whose package folder is `pvj/` as well as `mctl/` (a rollback bundle of the release before), and tools/make-release.sh builds from either folder name. A test for the first is in test_update.py. bin/nxlx-convert's own table still says pvj/ to mctl/, as it is for old nodes: the rename tool had turned it into mctl/ to mctl/, which was put back.
- Tests that run the code of an older commit (git archive of a pinned commit with the folder pvj, run with PYTHONPATH on it): the scripts they run keep `from pvj ...`, and what they read of the old tree keeps "pvj". The converter test stages its old node from this tree and renames the staged package folder to pvj. test_https reads origin/master's settings.py from mctl/ and, failing that, pvj/ (until this PR is on master, master still has pvj/). The CI job that runs the new NDI tests against the code that was stuck on the Pi (pvj.yml) now also rewrites the copied tests' `mctl` to `pvj`, as it already did for the header and cookie.
- The names the table has no row for stay and are listed in the PR text (the system layer, the bundle names, the group pvj in the tests of the accounts, the desk's runtime folder `$XDG_RUNTIME_DIR/pvj` in paths.py).
- Tested here: see the PR text. Open: the job that runs the old Pi code (needs mpv 0.40) and the real-install and real-convert jobs ran on CI only.
- Review of 300: (1) The updater installed on a node before the rename reads pvj/__init__.py and pvj/settings.py of a bundle and refuses one without them, and rollback() never looks at a bundle, so the compat in mctl/update.py did not help old nodes. tools/make-release.sh now adds those two files to the bundle as stubs (the __version__ and SCHEMA lines only) for one release; install.sh copies only mctl, bin and render, so they are never installed. test_release runs master's own inspect_bundle (git archive of 1057087) on a bundle the script built, runs install.sh --stage on it and checks no pvj folder lands in the release. The stubs go with the one-release window; when PR 7 renames bin/pvj-player and bin/pvj-web the old updater's checks for those need stubs too. (3) The picture helper's unit named mctl/fonts and a rollback to a pvj-layout release does not write units again; the unit now runs /bin/sh -c and takes mctl/fonts if it is there, else pvj/fonts (test in test_graphics.py runs the command on both layouts). (5) The old-code job's rewrite of the copied tests is narrowed to "mctl." and "mctl ", "mctl" in quotes and a path starting mctl/. 299 (release 0.1.1) must not be deployed alone: only with this PR does the node get the mctl layout. The allow list now counts the 0.1.1 journal's two old names.
- bin/nxlx-convert reads the programs a converted unit runs from ExecStart; it now also reads the program after exec in the picture helper's /bin/sh -c line, so a node that had the helper still needs render/nxlx-raster (test_nxlx_convert).
