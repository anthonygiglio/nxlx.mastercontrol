## 2026-11-07, the server's own words say node (`node-words-backend`, the second half of D121)

- **What.** 148 messages of `pvj/*.py` that a person reads say node where they said box: the API's errors, the states the panel shows (Health, the room job's "Node: playing"), and what the set-up commands print (pvj-ndi-runtime, the discovery server). Same rule as the panel's half (#202, D121): only the words, never a key, a file, a unit, a package or the certificate's name. Left as they were: log lines and docstrings, the lines written into files on the node (`# Written by pvj-ndi-runtime ...`), "fader box", and the installer's own log lines (`install/install.sh`). After #201 merged, `pvj/renderer.py`'s six messages followed (latescreen.py and player.py had none). What `pvj-ndi-runtime status` prints is read by a person, so it follows too. A render node's cue now says "left this node, not that the render node took it", where a plain swap would have said "the node" twice for two machines.
- **Tests.** 20 test files quote the new words: the modules that check these messages, and the browser test's quotes of the server (the OSC warning, the Health line, the room job).
- **Run on the HP's WSL:** the whole unit suite (3857 tests) after the change; every failure but two was a quote of the old words, now changed. The two others, `test_release` (a git clone of a worktree) and `test_rootfs` (media on the root), fail the same way on master's code here, so they belong to this machine, not to the change. The changed modules and `tests/ui/panel.test.js` were run again after the tests were brought along.
- **The review** (the coordinator's): the real-install test greps `pvj-ndi-runtime status` for the old words (now node); a failed send to a render node says "this node could not send to" so it never reads as the render node failing; `pvj/NDI.md` quotes the new status line; one test docstring said both words. Master (with #202) merged in; room.js and app.js already said node.
