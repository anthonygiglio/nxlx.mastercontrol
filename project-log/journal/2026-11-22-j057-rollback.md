## 2026-11-22, J-057: the Rollback button on the Updates card

- Built on branch `j057-rollback` from master 212e7355: the Updates card (Owner only) shows the release that runs and the one before it with its date, and a "Go back to N.N.N" button with an in-page question; the route `POST /api/system/update/rollback` asks nxlx-sysd, which starts the new fixed unit `nxlx-update-rollback@N.N.N.service`, which runs the existing `nxlx-update rollback --version N.N.N` (D150). The panel runs nothing as root.
- `nxlx-update rollback` now takes `--result` and `--version`; the progress file gets `"action": "rollback"` and a "running" line at the start. Without `--version` it is the call it always was.
- Refusals shown in plain words on the card and as a 409: read-only disk, no previous release, release with the old names (names `sudo nxlx-convert --undo`), update or rollback running, care job running, previous release changed since it was shown.
- Remote support: refused through the tunnel (`support.REMOTE_DENY`), unlike the update upload, because a rollback puts old settings (PIN, devices, support switch) back. D150 says why.
- Event log: a line at the start with the role (Owner), and "Rollback finished/failed" at the end.
- Tests: `tests/test_rollback_button.py` (new, 27) and rows in test_roles, test_carried_roles, test_support_reach. Not run on a node: the unit, the real restart, the page in a browser and the older panel coming back after a rollback are unproven.
