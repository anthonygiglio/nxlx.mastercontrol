## 2026-11-22, J-050: a kept settings disk for the read-only system disk

- The problem: with the read-only disk on (nxlx-rootfs enable), everything written after boot lives in RAM, so the PIN, scenes, Owner and staff devices, uploaded graphics, the node's settings and the Wi-Fi were all lost at each restart. The owner decided a kept settings folder is wanted.
- The approach (D148): one small ext4 filesystem outside the read-only root, found by the UUID saved in /etc/nxlx/kept.json, with six folders on it bind-mounted over /var/lib/nxlx, /var/lib/nxlx-player, /var/lib/nxlx-netd, /var/lib/nxlx-update, /var/lib/nxlx-support and /etc/NetworkManager/system-connections (the saved Wi-Fi) by install/nxlx-kept.service at boot, before NetworkManager and the nxlx services. The spec (rootfs-updates, option D-lite) offered a writable place for state only; a bind mount of folders was chosen over a repartitioned root or releases on the writable partition because it leaves the install and the update path (J-174) untouched and is testable with a temp folder and a fake mount.
- New: mctl/kept.py (class Kept: boot, check_for_enable, prepare, status; copy_tree), bin/nxlx-kept, install/nxlx-kept.service. install.sh installs and enables the unit and the link (enabled, never started there; its condition skips it without kept.json) and removes both on uninstall. mctl/rootfs.py: enable calls Kept.check_for_enable and is refused in plain words with no ready kept disk (--without-kept is the way to the old behaviour, with a warning), a media folder in /var/lib/nxlx counts as kept, status shows the kept disk, disable says the kept disk stays in use. The convert test lists the new unit and link among what an undo leaves (they have no old name).
- Safety: the first boot copies each folder as root with descriptor-relative, O_NOFOLLOW opens, only plain files and folders, owners and modes kept, set-id bits on files dropped, into a .new folder renamed into place when complete and flushed; a kept folder is never overwritten. A folder is bound only if the kept copy and the place it covers are real folders reached by no link. A missing disk, a wrong marker, a bad config, a full disk or a failed mount leave the folders as they are and write the reason to /run/nxlx-kept.json (active, partial, missing, refused, off). The J-178 guarantee holds: /var/lib/nxlx-update is its own kept folder (root 0700 kept), never inside the panel's. J-175 and J-177 (no following links in the state folder) are matched by the copy; the installer's checks run unchanged through the bind mount. J-174 is untouched.
- Wi-Fi: NetworkManager's saved connections are the "wifi" folder (keyfiles, mode 0600 kept), mounted before NetworkManager starts.
- Tests: tests/test_kept.py (copy rules and links, first boot, a write surviving a simulated restart, no second copy, missing disk, bad marker, bad config, link at the mount point or the folder or the kept copy, full disk, cut-short copy, one e2fsck, idempotence, the enable check, prepare, the rootfs enable and disable, the unit), tests/test_install.py (unit and link installed and removed), tests/test_install_convert.py (the undo list). Real node: nothing. tools/DEVICE-TESTING.md has KS1 to KS8 (the pull-the-plug test is KS5) and RA14 now says --without-kept.
- Not done, for the second PR: stop using the kept disk (copy back, then no binding), a panel card for the state in /run/nxlx-kept.json, the journal on the kept disk, a partition made by the image (J-168) or a helper that shrinks the root partition, and a guard against the kept disk filling up (media is the risk: it lives in /var/lib/nxlx by default).
