## 2026-11-22, J-050: a kept settings disk for the read-only system disk

- The problem: with the read-only disk on (nxlx-rootfs enable), everything written after boot lives in RAM, so the PIN, scenes, Owner and staff devices, uploaded graphics, the node's settings and the Wi-Fi were all lost at each restart. The owner decided a kept settings folder is wanted.
- The approach (D148): one small ext4 filesystem outside the read-only root, found by the UUID saved in /etc/nxlx/kept.json, with six folders on it bind-mounted over /var/lib/nxlx, /var/lib/nxlx-player, /var/lib/nxlx-netd, /var/lib/nxlx-update, /var/lib/nxlx-support and /etc/NetworkManager/system-connections (the saved Wi-Fi) by install/nxlx-kept.service at boot, before NetworkManager and the nxlx services. The spec (rootfs-updates, option D-lite) offered a writable place for state only; a bind mount of folders was chosen over a repartitioned root or releases on the writable partition because it leaves the install and the update path (J-174) untouched and is testable with a temp folder and a fake mount.
- New: mctl/kept.py (class Kept: boot, check_for_enable, prepare, status; copy_tree), bin/nxlx-kept, install/nxlx-kept.service. install.sh installs and enables the unit and the link (enabled, never started there; its condition skips it without kept.json) and removes both on uninstall. mctl/rootfs.py: enable calls Kept.check_for_enable and is refused in plain words with no ready kept disk (--without-kept is the way to the old behaviour, with a warning), a media folder in /var/lib/nxlx counts as kept, status shows the kept disk, disable says the kept disk stays in use. nxlx-convert --undo removes the unit, its sysinit.target.wants link and the command link (they have no old name, so no journal record would); the real-install test ("the undo left names of this release") needs that, and the convert test checks it.
- Safety: `nxlx-kept prepare` (an admin, node up, services stopped for the copy, one syncfs at the end, never at boot) copies each folder as root with descriptor-relative, O_NOFOLLOW opens, only plain files and folders (relative links without .. are kept), owners and modes kept, set-id bits on files dropped, into a .new folder renamed into place; a kept folder is never overwritten. Review round: prepare makes every check (partition table, system disk, blkid errors, mount point, existing config) before it writes; the disk is accepted at boot only with the random secret of prepare (/etc/nxlx/kept.secret, constant-time compare, O_NOFOLLOW, size cap); boot never raises and logs non-UTF-8 names safely; after the seed the system disk's old copy is emptied of devices, recovery codes, pairings, update settings copies and the support key. A folder is bound only if the kept copy and the place it covers are real folders reached by no link. A missing disk, a wrong marker, a bad config, a full disk or a failed mount leave the folders as they are and write the reason to /run/nxlx-kept.json (active, partial, missing, refused, off). The J-178 guarantee holds: /var/lib/nxlx-update is its own kept folder (root 0700 kept), never inside the panel's. J-175 and J-177 (no following links in the state folder) are matched by the copy; the installer's checks run unchanged through the bind mount. J-174 is untouched.
- Wi-Fi: NetworkManager's saved connections are the "wifi" folder (keyfiles, mode 0600 kept), mounted before NetworkManager starts.
- Tests: tests/test_kept.py (copy rules, links, hard links, pipes and sockets, no per-file flush, the boot copying nothing, a write surviving a simulated restart, missing disk, bad marker and secret, a secret that is a link or a pipe or huge, bad config, link at the mount point or the folder or the kept copy, one e2fsck, idempotence, a failing folder not stopping the next, non-UTF-8 names, the enable check with a linked media folder, prepare with a partitioned disk, a failing blkid, the system disk, every check before any write, the services stopped and started and one flush, the emptied old copy, a failed copy undone, seed, the rootfs enable and disable, the unit), tests/test_install.py (unit and link installed and removed), tests/test_install_convert.py (the undo list). Real node: nothing. tools/DEVICE-TESTING.md has KS1 to KS8 (the pull-the-plug test is KS5) and RA14 now says --without-kept.
- Second review round (PR 319): the scrub now follows the commit and also takes out fleet.accept, fleet.json, fleet.sig and pairings.json (deny.json stays); prepare and seed restart the services on any exit including SIGTERM, SIGHUP and SIGINT, stop services that are still starting, refuse while a conversion undo is armed or an update or USB copy runs, flush before and after each rename and try every bind; --wipe replaces a disk in use; the boot step is installed at /usr/local/lib/nxlx (bin/nxlx-kept-boot and kept.py) so a rollback cannot take it away; a second-pass-only undo no longer removes the kept unit and files.
- Not done, for the second PR: stop using the kept disk (copy back, then no binding), a panel card for the state in /run/nxlx-kept.json, the journal on the kept disk, a partition made by the image (J-168) or a helper that shrinks the root partition, and a guard against the kept disk filling up (media is the risk: it lives in /var/lib/nxlx by default).
