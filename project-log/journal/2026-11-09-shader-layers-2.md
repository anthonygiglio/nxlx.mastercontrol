## 2026-11-09, shader transitions slice 2: fades into and out of a shader (renderer and player)

- Built slice 2 of design/shader-transitions_2026-11-08.md (D130): pvj-render 0.10.0. New socket command `["pvj-fade-to-program", PATH, SECONDS, MOVE?]` builds a generator program into the idle layer, makes that layer the front and fades to it (the mix, or a wipe or slide). The property gains `program-fades` (a count; there from 0.10.0, so a panel can tell it from 0.9.0, which has `layer-generators` and no command).
- The IPC thread builds nothing: it hands the program to the idle layer's mailbox and waits for the render thread's answer (at most 3 s), as `pvj-shader load` does. The old picture, a clip or a program, plays on meanwhile. The fade is made only after the answer, and its clock starts at the program's first drawn frame (`fx_layer_started` in the render loop, which now draws the front layer's generator before it looks at a waiting fade). A program the GPU refuses answers with its words and changes nothing; a fade that was running has by then ended on its incoming side (D98's rule for any load: the idle layer is that fade's outgoing one and cannot be built into). A build that outlasts the 3 s wait is answered so and the program is asked off, so it never shows later on a layer that is not the front.
- `pvj-crossfade` out of a layer whose picture is a generator is now a fade even when the layer's clip is idle (before, an idle clip meant "nothing to fade from" and the clip was cut in). With neither a clip nor a program on the screen, a fade into a program is a cut from black, as a clip is.
- Lock order: `fx_lock`, then `layer_lock`, then `app.lock` (the order `pvj-shader load` already took them in). `layer_lock` is held across the build so a crossfade cannot take the idle layer meanwhile; other commands that take it wait at most the build (3 s).
- Player (pvj/player.py), not yet asked by the panel: `Player.layer_generators()`, `fades_native()` and `fade_to_program(path, seconds, style, epoch)`; `play(..., fade=)` out of a program of the renderer's own is a fade and lets the renderer free the outgoing program, where it used to take the source off first. The panel still chooses with `fades_from_clip()`, so nothing it does changes before slice 3.
