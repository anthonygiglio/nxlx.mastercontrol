## 2026-11-19, Test-only follow-ups from the review of PR 307 (J-174).

- tests/test_install.py ReadOnlyRootTest: the two tests that passed --dry-run could not fail, because --dry-run skips the read-only check altogether. The normal-root and docker-overlay test now runs without --dry-run as a non-root user and expects the "run as root" refusal and no read-only sentence. In install.sh the overlay check comes before the root check, so "run as root" does not hide it: a wrongly refused overlay would give the read-only sentence instead. The stage test keeps one --dry-run run (the only thing that stops an overlay root being refused there) and gains an overlay run with --stage alone, which must get past both refusals. Both skip when run as root, since the installer would then run for real.
- tests/ui/panel.test.js: the "every Install button is disabled" check had no bundle in the list, so it passed for nothing. The mocked answer now carries one usb bundle; the read-only run asserts at least one Install button and that all are disabled, and the normal run asserts the button is enabled.
