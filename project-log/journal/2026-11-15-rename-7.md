## 2026-11-16, second review of 301: the carried-file check, a torn journal, a change cut off, and CI

- CI real-install: the panel writes a new PIN hash into settings.json at every start, so the test's byte check after the start always failed. The test now checks that the converter found the file the same before the start (its journal record) and that everything but the auth section is still the same after it.
- CI real-convert: the plan ran two seconds after the old player started; its socket was there but it had not answered yet, which the converter counts as a show playing. Not the 5 second limit of the last round: the 2 second read timeout was already there. The test now waits, at most 60 seconds, until the player says it is idle, before the first plan and before the run after the player was restarted.
- (M1) The converter compared settings.json with the first run's hash after step 9 had started the panel, which rewrites it: a re-run after a step-9 failure always failed, and a normal run raced the panel. It now compares once, after the last change and before the start, writes the result in the journal ("carried-same"), and a run that carries on does not compare again once that is there.
- (M2) One unreadable journal line crashed --state, --run and the timed undo, and install.sh reads the journal on every install. A torn last line (a power cut while writing) is passed over with a warning and moved aside into a copy of the journal before the next record; an unreadable line anywhere else refuses, cleanly, with nothing armed or changed. A whole last record without its newline gets one before the next.
- (M3) A change whose "done" was never written (a power cut) was not undone: with no other change, the timed undo said "Nothing to undo" and took the timer away. The undo now also puts back a change that was begun without its end, which is safe whether or not it was made (each undo looks first, or puts back the original), and a stop begun that way counts for what is started again.
- (L1) install.sh changes --user pvj-player (and the other converted accounts) to the new name whenever the node has the new layout, not only in the run that converts, so a later install never makes a second account; another pvj-* name is refused.
- (L2) A timer with no conversion in its journal (the journal lost) is taken away by --confirm and --undo, which returned early before.
- (L3) A "previous" that is a link or a folder is refused by the plan with --release, instead of failing at change 5 after the folders moved, and in every run after.
- `--run --release X` with X already current left "previous" with the old path (step 6 skipped it, and step 5 did not write it). Step 6 now rewrites it whenever step 5 does not.
- Tests: the check before the start and the carry-on after it; a change before the start still fails; a torn last line and a bad middle line; a power cut after five different changes, then the timed undo, back to the old node exactly (NXLX_CONVERT_CUT_AT stops the process dead after a change, in stage mode only); a timer without its journal; a "previous" link refused by the plan; X already current; --user pvj-player after the conversion. Each new test fails on d946067.

## 2026-11-15, review of 301: a conversion cut off half-way, step 9, and root reading the panel's files

- (1, high) install.sh saw an old node only by /opt/pvj, /etc/pvj and /var/lib/pvj, which the converter renames first: a re-run after a cut-off did a plain install, left old units beside new ones and moved "current" itself, outside the journal, so the undo left current pointing at nothing. Now install.sh asks the converter (`nxlx-convert --state`: none, pending, unconfirmed, confirmed, undone) and carries a pending conversion on with `--run --release`; it never switches current or writes previous after a conversion or while one waits for its confirm, and refuses another version then. The converter writes "previous" itself with --release (a journaled "put", undone with the rest). An armed undo timer alone also counts as waiting for the confirm, whatever the journal says. The confirm reminder is printed whenever the undo timer is there.
- (2) A run whose every change was made but whose start and check (step 9) failed was "Nothing to convert" for the next --run and could never be confirmed. The next --run now re-arms the undo, starts and checks again and finishes the run. In stage tests NXLX_CONVERT_FAIL_AT one past the last change stands in for step 9.
- (3) The real-install grep for old names now reads only non-comment lines, and the tmpfiles comment no longer names the old paths; two `a && b || fail` lines (SC2015) are if-blocks.
- (4) The converter's sha of what is carried over and its open of the update locks go through plain files only (no link, no fifo, no device, capped size), so a fifo in the panel's folder or in /run/lock cannot hang root, and a link to /dev/zero cannot eat memory.
- (5) install.sh refuses, before anything changes, a --user pvj-* the converter does not rename. (6) The player check has one overall limit of 5 seconds.
- Tests: install.sh cut off at change 5, at change 30 and after the last change, re-run, then confirmed or undone, back to the old node exactly (test_install_convert); another version refused while a conversion waits; a step-9 failure finished by the next run and confirmed; pipes and links in place of the settings and the lock; a player that sends lines but never the answer.
