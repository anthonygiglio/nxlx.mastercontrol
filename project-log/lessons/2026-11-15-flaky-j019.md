## A wait that needs several looks in a row needs a quiet machine; a route comes off only when no answer is in flight (2026-11-15)

Three steps failed only under load, and both were timing that the test had written as a coincidence. The strobe press waited for three looks in a row inside half a second of a two second clip; with each look slowed by load they never fit, and 20 of 20 tries under load failed. The status route was taken off with page.unroute() while an answer from it was still on its way, and the fulfill that followed threw "Route is already handled" (86 errors in 40 take-offs). The third cleared a note that another thread had not yet made: the test saw the effect on, and the hub noted the held control just after.

What we do now: a test that reaches into another thread's state waits for that state to exist before it changes it. Wait for the one condition the next step needs (one look in the window), not for a run of looks that must all fit in it. Take a route off through the patched page.unroute (tests/ui/routes.js), which lets the answers in flight finish first. To reproduce a flake like these, run the step on its own in a loop with a bounded set of busy loops beside it, count failures before and after, and stop only the loops whose process numbers were kept.
