## D138. The protocol names move to mctl, and for one release a node still reads the old ones: it accepts both and sends the new (2026-11-14)

What: rename PR 4 (kind protocol of D135). The OSC family /pvj/... is /mctl/... (state sent back /mctl/state/...), the header X-PVJ-Request is X-MCTL-Request, the cookies pvj_token and __Host-pvj_token are mctl_token and __Host-mctl_token, the server banner and the peer user agent are mctl and mctl-peer, and the panel's browser key and window globals are mctl.nodes.opened, mctlApp and the rest. For one release a node also reads the old names. Why: the owner's answers of 2026-11-11 (no sign-outs: the old login cookie is read for one release and swapped quietly), and the builder's brief for this pull request: a client that still sends the old names keeps working for one release. This replaces the assessment's "old header refused, old OSC address refused (clean break)" for PR 4. Cost / rules out: the old names stay in four files (pvj/server.py, pvj/osc.py, pvj/web/app.js, tools/boxcert.py) and in tests/test_old_clients.py until a small pull request removes them in the release after the node cutover; the guard's allow list counts them.

The rules, each with its reason:

1. **OSC: an address of the old family means the same address of the new one** (`osc.current`, in the receiver and in `translate`), behind the same locks: the key prefix (`/k/<key>/pvj/stop`), the device list and the paired-device rule hold exactly as for the new family. The owner's TouchOSC layout (outside the repository) and any Max, Resolume or QLab patch keep working without being redone. What the node sends back follows the target (the coordinator's decision after review): a target that asked for everything with /pvj/state gets its state as /pvj/state/... until it asks with /mctl/state, so the owner's layout (4 such addresses) keeps showing state; a target set by hand that never asked gets the new family.
2. **The header: either name with the value 1 passes**, and the Origin check is unchanged for both. The panel and the peer calls send the new name only. tools/boxcert.py sends both for one release, because it runs on the owner's computer and may meet a node that is not updated yet; a node that has not updated reads only the old one.
3. **The cookie: the new names are read first, then the old ones** (the secure old name over TLS only, as the new). A request signed in by an old cookie whose token is still paired (a device or a support login) gets the same token under the new name of the same strength (only __Host-pvj_token becomes __Host-mctl_token; a plain pvj_token, which plain http could plant, becomes the plain mctl_token even over TLS), for the life a new cookie of that kind has, and the old names expired. A request that also shows an old cookie beside a new one, or a Bearer token, gets only the old cookie expired. A logout that shows an old cookie clears it too. Nothing is set for a token that is not paired. The token itself never changes, so no device is paired again.
4. **The browser key: the panel copies pvj.nodes.opened to mctl.nodes.opened once, if the new key is empty, and removes the old.** The list of nodes a device opened survives.
5. **The old PHP panel stays as the upstream original.** index.html sends X-PVJ-Request and security.php checks it; no node installs or serves them (install.sh, the image and make-release.sh ship pvj/, bin/, install/ and render/ only), so no client of a node is affected, and renaming one side alone would break the pair. They are kept with the credited original (decision B), and tests/security_test.sh, which tests that panel, keeps its header; it is in the apply script's SKIP list.
6. **Nothing else in the repository needed a bridge.** No TouchOSC layout in the repository holds a pvj address (sync/PocketVJ_OSC.touchosc uses only the upstream addresses), the three controller maps use action names, and the FireTab launcher is not in this repository and has no pvj name (assessment 3.12). The peer listener does not read the header, so two nodes on different sides of the rename still call each other.
