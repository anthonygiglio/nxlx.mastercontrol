## D136. A node moves to the new names through one converter, nxlx-convert, which plans first, backs up, journals every change and can undo it (2026-11-14)

What: `bin/nxlx-convert` (standard library only) moves a node's live state from the old pvj names to the NXLX names: the service accounts and their groups (the shared group pvj becomes nxlx-svc), the folders under /opt, /var/lib, /etc and /media, the unit files with their drop-ins and wants links, the udev, tmpfiles, journald and modules-load files, the command links in /usr/local/bin, the text files it owns (install.json, the env file, allowed_signers, support.json, the release's "previous" note), and last the deploy and login account pvj-dev with its home and sudoers file. `--plan` is the default and changes nothing; `--run` backs up, arms an undo, stops the services, converts, starts and checks; `--confirm` keeps it; `--undo` walks the journal backwards. `--root DIR` is stage mode, as `install.sh --stage`: it works on a copy of a node and never calls usermod, systemctl or systemd-run. This is PR 2 of the rename plan (the owner's spec and assessment of 2026-11-11, section 4); it ships the converter and its tests, and nothing calls it yet.

The rules, each with its reason:

1. **The plan is worked out from what is on the node, never from the journal.** A name that is only old is converted, a name that is only new is done, a name that exists under both is a refusal. So a second run finds nothing to do, and a run that stopped half-way carries on with `--run` or goes back with `--undo`. The tests fail a run at many points and check both ways back.
2. **Ids stay, names change.** groupmod and usermod rename in place, so every file keeps its owner and nothing is chowned. settings.json (the paired devices' token hashes and the PIN's hash), the node id and the certificates are carried over byte for byte and checked after the run: nobody is signed out by the conversion and the signed fleet list still matches the node. The cookie bridge of decision A belongs to rename PR 4.
3. **Nothing is deleted.** Every rewritten file's original is kept beside the journal; a root-only tar (0600, folder 0700) holds the account files, the settings, the node id, tls/ and every system file a step touches. The videos and the releases are not copied: their folders are only renamed, on the same file system. Leftovers such as an interrupted install's releases/X.new are listed and move with their folder.
4. **It refuses rather than guesses.** A current release that does not have the programs the converted units and links run (every /opt/nxlx/current path of their Exec lines; a program behind ConditionPathExists, such as the picture helper, only when the node had it before) (a release from before the rename would leave the node dark until the undo), a show that is playing (the player's mpv socket says it is not idle, or it does not answer), an update that holds the update lock, a read-only root, a USB drive mounted under /media/pvj, an account to be renamed that has a process outside its services (an ssh login: run it from another admin login), a new name that exists already. Only the show can be overridden, with `--force`. The owner's node-02 case, a player that runs as pvj-dev, is allowed: that process is in the player's unit and stops with it. Every loaded pvj-* unit is stopped (the picture helper's per-job instances too), and the run checks that no process of an account to be renamed is left before it renames any. `--undo` makes the same in-use check; the timed undo, which cannot wait, puts back everything but a logged-in account, and leaves that account's home, sudoers file and sub-id lines with it.
5. **On a real node it protects itself.** `--run` re-starts itself in a transient unit with no terminal (its report goes to the journal and to the run's log file, and a terminal that goes away is ignored), so a dropped ssh connection cannot stop it half-way. The undo timer is a unit file in /etc, enabled, with OnActiveSec=15min and OnBootSec=5min, so it also fires after a power cut in the middle of a run; it runs a copy of the converter kept beside the backup (its own folder moves during the run). A run that carries on stops, resets and re-arms it. A manual `--undo` runs detached the same way. One lock in /var/backups/nxlx-convert lets only one of `--run`, `--undo` and `--confirm` work at a time; `--confirm` refuses while the timed undo runs and never stops it, and confirms only a latest run that finished and was not undone. `--confirm` removes the timer; the timed undo never undoes the latest conversion once it is confirmed, a manual `--undo` still can. Every run that is not undone counts when the services are started again, so a run that carries on starts what the first one stopped.
6. **One table.** The rows a node's files can hold are copied from tools/rename-map.txt into the converter (it must run alone on a node) and a test keeps the two equal. Release names (signing namespace, bundle and USB names) are held until rename PR 8 sets `RELEASE_NAMES_LIVE`. Unlike the apply script, a held row does not shield its text from the live rows, because on a node `/run/pvj-update/` starts with the USB folder's row `pvj-update/`. A sudoers file name such as 010_pvj-dev is renamed by its own rule, since `_` is no word boundary.

Why: the cutover changes the names an admin, systemd, sudo and the deploy scripts depend on, on two nodes, with the owner away; a converter that cannot be undone, or that leaves a node half-renamed after a dropped connection, is the one way this rename can lock him out. Cost / rules out: nothing runs it until rename PR 7 (install.sh calls it on an old layout) and the cutover after PR 8; the real-node paths (usermod, systemctl, visudo, the timer) are not covered by these stage tests and need the real-install CI job the assessment names before the cutover.
