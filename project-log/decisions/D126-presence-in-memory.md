## D126. The node knows who is connected and what each last changed, in memory only (2026-11-07)

Anthony asked whether a node knows a controller is connected and whether people see the other active controllers. Until now `auth.last_seen` held a device's last request in memory but was never told to anyone, and the file kept a time at most once a day (for the idle expiry of a guest's device).

**Connected now** is a request in the last 30 seconds (`pvj/presence.py`). The panel asks for the status every second while it is visible, so an open panel is always in; a tab in the background drops out after about 30 seconds (browsers slow a hidden page's timers) and returns with its next request. The panel says so; it is a count of seconds since the last request, not a promise that someone looks. Every request through `Api.handle` marks its device; the node's own callers (MIDI, OSC, DMX, the Room) are not people and are not marked. A support login is marked as its own entry.

**What is told to whom** is in `GET /api/status` under `presence` (the panel already asks for it every second, and the reply is a few hundred bytes). The rule follows what the node already hides: `GET /api/devices` does not show an Owner's device to an Operator, and a support login is kept from names (D125). So: the Owner sees every connected device by name and role, and a remote support session as "Remote support". An Operator sees the Operators' devices by name and role, an Owner's device only as the role "Owner" with no name, and the Guests only as a count (`guests`). A support login through the tunnel sees no device name at all, whatever its role: roles and counts only, and its own entry as "Remote support". A Guest sees `count` and nothing else (`devices` empty, `guests` 0). Never an address, a token or an id: an entry says only whether it is the asking device. The last ten changes follow the same rule for `by` (the name) and `role`: for each, the control area, whether it was this device, seconds ago, and who only as the viewer may be told it (an Operator is told an Owner's change as "Owner" and a Guest's as "Guest", without names; a Guest is told only the area and the time); a support change is told to the Owner and to support itself.

**A change** is a request that went well and changed a control, by area (Playback, Mix, Pads, Vibes, Shaders, Effects, Mapping, Projectors, Room, Sound, Tempo, Renderer, Screen, Network, Schedule, Controllers, Sources, Media, Look, Modules, System). Sign-in, devices, codes, access, HTTPS, recovery and the support tunnel are never a change here and are not told, and neither is a request that only looks or waits: a Wi-Fi scan, showing the OSC key (only a new key is a change), starting or cancelling MIDI learn. A removed device (a revoke, an idle guest, a factory reset) leaves the list and the changes at once. Requests the server answers outside the route table (a clip upload, a software update upload, a settings import) mark the device as connected and count as Media and System changes. The last ten are kept, newest first.

**Memory only.** Nothing in this is written to the disk, the card or the settings file, and a restart of the panel empties it. Cost / rules out: it is not a history (see the event log, D125, for what happened), a device that has the panel open in a hidden tab shows as gone after 30 seconds, and the Guests are counted, not named, to an Operator, so an Operator cannot see which guest did what. The panel side (a line "Changed by iPhone 12 s ago" on a card) reads this reply.
