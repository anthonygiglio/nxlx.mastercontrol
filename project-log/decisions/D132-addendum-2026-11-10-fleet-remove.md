## Addendum to D132 (2026-11-10): slice 4d, removing a node from the cluster and Allow again

- **Deny epochs and local tombstones.** Each row of the deny file has an integer epoch (1 for a first removal). Allow again deletes the row and keeps a tombstone (key, name, epoch + 1) in the same file, never sent to a peer. A deny from a peer is taken only when its epoch is above this node's row (a renewal) or tombstone; equal or lower is ignored without a word. The digest covers (key, epoch). Why: without a memory of the lifting, the next hello from a node that still held the deny brought it back (slice 3, item 9b). What it costs: after an Allow again, this node and a node that still holds the old deny keep different digests, so a hello between them always carries the removals and is answered; the caps per sender bound that. What it rules out: a peer lifting a deny, or undoing an Allow again, by any message.
- **The Allow again request is checked against the epoch the Owner saw.** A replayed request meets a newer epoch and gets 409. The fingerprint is typed back as in an acceptance; "allow again everything one node denied" needs no fingerprint (the Owner chooses the node, each row records who sent it) and works only on rows taken from a peer.
- **Push, with allowances of their own.** A removal is pushed in a hello (up to 24 rows), by one background pusher, charging a failed push to its target only. The receiver reads at most 12 pushes a minute per caller key and still answers the call. A node that takes a removal passes it on. Unreachable nodes are retried every 5 minutes from the lease worker and catch up on their own next hello. What it rules out: any use of the node-wide outbound count or of a count an outsider can fill.
- **A compromised approved node may spread denies (accepted), and cannot allow anybody.** Its denies are taken within the caps of slice 3 and shown in a banner (red above one a minute). The way back is on this node only: remove that node, then "allow again everything it denied".
- **Left out on purpose: `clear` in a signed list, `boxcert.py fleet clear`, and dropping a deny when a newer list leaves the node out.** The owner chose Allow again over re-signing; they are not needed for the action and stay open for a later slice. The removed node is not told by a message: every approved node refuses it, which is the protection.
