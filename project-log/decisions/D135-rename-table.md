## D135. The rename has one table, one script that applies it, and a guard that keeps it from sliding back (2026-11-14)

What: the old pocketvj and pvj names are renamed to NXLX and Mastercontrol names from one table, `tools/rename-map.txt` (old, new, kind, note on each line). `tools/rename-apply.py` applies chosen kinds of it to a checkout, a dry run unless `--write` is given. `tests/test_old_names.py` fails when a file holds more old-style names than `tools/rename-allow.txt` allows it (in its text and its file name), or when a file that is not listed holds any. This is PR 1 of the rename plan (the owner's spec and assessment of 2026-11-11, `nxlx_shared/specs/rename-pvj-spec.md` and `rename-pvj-assessment.md`); it changes no behaviour.

The rules, each with its reason:

1. **The prefixes.** nxlx for what an admin sees on a node (services, accounts, folders, commands, environment variables); mctl for what a performer, a device or other software sees (OSC `/mctl/...`, the header `X-MCTL-Request`, the cookie `mctl_token`, browser keys, the Python package, the renderer `mctl-render`). The owner's answers of 2026-11-11. The renderer is mctl-render, not nxlx-render, because nxlx-render-node already means the Max/Jitter render node.
2. **The shared service group is nxlx-svc**, not nxlx: node-01 already has a login user and group called nxlx. The deploy and login account pvj-dev is part of the rename (nxlx-dev).
3. **One kind for each pull request of the plan**: text (PR 3), protocol (PR 4), render (PR 5), package (PR 6), system (PR 7), release and env (PR 8), ci (PR 10), plus keep for phrases that never change (the credit "PocketVJ CP v3", the upstream repository and web site). The assessment named six kinds; render and release are added so PR 5 and PR 8 can run alone.
4. **Exact rows, longest first, with word boundaries**, and a few families (`PVJ_*`, `pvj_*`) where every name of the family follows one rule. "pvj" on its own is ambiguous (the package, the group, prose) and has no row: the script reports such places as not covered, and the pull request that needs them adds a row with enough context. A blind replace would have taken systemctl for mctl and pvj-ndi for part of pvj-ndisc.
5. **A row of a kind that is not chosen still holds its text.** Applying render leaves the CI job name "pvj-render (Ubuntu)" alone, which is a required check of "Protect master" and is renamed last with the ruleset.
6. **Never rewritten:** the credit (LICENSE.md, AUTHORS.md, NOTICE.md), the upstream code, panel and manual as at the last upstream commit (sync/, js/, assets/, themes/, the upstream files of docs/, index.html, backend.php and the other PHP files, RELEASE_NOTES.md), and security.php: the fork's hardening of the old PHP panel shares the pvj_ function names and the X-PVJ-Request header with the upstream files it guards, so the two move together or not at all. The owner kept the upstream manual as the credited original (decision B of the assessment).
7. **The guard counts, it does not forbid.** Today about 10,700 old-style names sit in 683 files (this pull request's own log included); each file has a ceiling, the list only shrinks (`rename-apply.py --write-allow` recounts it), and raising a number by hand is a choice a reviewer sees. At the end of the rename only the credit and the upstream original are left.

Why: about 840 distinct old names in 517 files cannot be renamed by hand ten times over without missing some, and the drafts and other checkouts need the same rename (`--root` applies it to another tree). Cost / rules out: a new old-style name now needs a line in the allow list until the rename lands, and the table must be extended (not worked around) when a pull request meets a name it does not cover. The owner asked that the project log be rewritten too; D107 and the "project-log" check forbid editing earlier log files, so PR 10 needs an addendum to D107 before it runs the table over project-log/.
