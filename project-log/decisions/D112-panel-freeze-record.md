## D112. A freeze made by a transition leaves a record, so a new panel can thaw it (2026-10-31)

When a transition freezes the outgoing clip, the panel writes `transition-frozen.json` (player process, file playing) in its runtime folder before the freeze, and removes it when the freeze ends. A panel that starts reads a leftover one, removes it, and unfreezes the clip only if the player process is the same, it is still paused and it still plays the same file; `tidy()` does this next to the sweep of `transition-<pid>` files. Why: a panel that died between the freeze and the load left the picture stuck, and the new panel could not tell that from a freeze by the operator. A hold that did not freeze anything (the operator had) writes nothing, so an operator's freeze is never undone. Cost / rules out: one small file written per transition that freezes; a freeze made by the operator in the very short gap between a load and the removal of the record, with the same file, would be undone at the next start (judged not worth a second mechanism); a record needs the player's `pid` and `path` to be readable, otherwise nothing is thawed; it does not help if the whole box lost power (the player is new then).
