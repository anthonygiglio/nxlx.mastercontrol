## D141. A node's time zone is set by an Owner, once confirmed it never changes by itself (2026-11-15)

The schedule fires by the node's local time, so the zone is part of what a show depends on. Rules: (1) only an Owner sets it, from the panel, and never through remote support (the route is in support.REMOTE_DENY); a Guest, an Operator, a controller and the schedule cannot. (2) The only automatic change is the first Owner pairing on a node that is still on UTC and whose zone nobody has confirmed: it takes the browser's zone and says so. (3) After an Owner has set or kept a zone (`settings["timezone"]["confirmed"]`), nothing changes it without an Owner's tap; a different browser zone is only offered ("Use Y?"). (4) The name that reaches `timedatectl set-timezone` is checked in the root helper (safe pattern, a real TZif file under /usr/share/zoneinfo, listed by `timedatectl list-timezones` where that can be asked) and the zone is read back. Why: a wrong zone moves every entry by hours with nobody in the room to notice, and a phone travelling or on a VPN must not move a node's schedule. Cost / rules out: a node that is first paired from a phone in the wrong zone is set wrong until an Owner corrects it (the Schedule page shows the zone and warns when it differs from the device in hand); a node that is not on UTC when first paired is left alone and only offered the change.
