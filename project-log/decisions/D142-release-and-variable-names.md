## D142. Release names change with no fallback: a bundle, a signature or a stick under the old names is not taken (2026-11-16)

What: rename PR 8 (kinds env and release of D135). Code reads only NXLX_* variables, the updater takes only nxlx-N.N.N.tar.gz (with .sig and .sha256), looks for the USB folder nxlx-update/, verifies under the principal and namespace nxlx-release, and the recovery stick file is nxlx-recover. The converter rewrites the variable names in /etc/nxlx/nxlx.env and the units, and the principal and namespace in /etc/nxlx/allowed_signers, as journaled changes that `--undo` puts back. Why no fallback to the old names for one release: (1) the owner chose a clean break for these, and the assessment's decision D says a bundle made before the cutover is re-signed, not accepted under both names; (2) a rollback bundle under the old names would be a release with the old program names, which the updater refuses anyway since PR 7 (no bin/nxlx-player), and the way back to such a release is `sudo nxlx-convert --undo`, which also restores the old variable and signing names; (3) a signature made under pvj-release cannot verify against nxlx-release, so accepting the old file name would not make an old signed bundle installable; (4) accepting the old recovery file name would keep the old name alive in a security feature, which the assessment advised against. Cost / rules out: a bundle built before this change that has the new layout (a 0.1.2 build under a pvj- name) must be renamed and signed again with the owner's key (`ssh-keygen -Y sign -f ~/.ssh/nxlx-release -n nxlx-release nxlx-N.N.N.tar.gz`, then the checksum; the command is in mctl/README.md); a stick that carries a pvj-update folder or a pvj-recover file shows nothing until it is renamed; a node that still has its old allowed_signers (not converted) refuses new bundles, which is the intended order: the first install of a release with these names is install.sh over ssh, which converts the node.

The variable names have no reader of the old ones: a node on an old layout has its variable names rewritten by the converter in the same run that renames its folders, and a node that took PR 7 gets a second pass with only those rewrites. Nothing is read under a name that nobody writes, except what a script outside the repository writes into a node's nxlx.env or units by hand.
