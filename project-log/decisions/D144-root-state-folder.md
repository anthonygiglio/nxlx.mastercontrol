## D144. Root's own state folder is /var/lib/nxlx-update (2026-11-19)

Root's update backups and the clip stick's claim live in /var/lib/nxlx-update, root:root 0700, not in /var/lib/nxlx. Why: the panel account owns /var/lib/nxlx and can rename anything in it, so it could hide root's backups across a factory reset and put them back, or replay the claim; a folder whose parent is /var/lib (root's) cannot be touched by it. The name follows the nxlx-<thing> pattern of /var/lib/nxlx-player and /var/lib/nxlx-netd and is one path in mctl/paths.py (ROOT_STATE_DIR). Cost / rules out: one more folder to make at install (install.sh does, so nxlx-sysd's ReadWritePaths exists), and a one-time move of older files (migrate_legacy_state); a root folder inside the panel's folder, even with checks, is ruled out.

The move is one time (review of PR 314): the first migration run writes a root-only marker, `migrated`, in the folder (O_EXCL, 0600), also when it found nothing, and a factory reset (nxlx-sysd clear_update_backups) and forgetting the clip stick write it too. After the marker, whatever is under the old names in the panel's folder is set aside or removed, never imported, so the panel cannot hide root's files, wait for a reset and put them back. What code cannot close: a panel that was already compromised before the very first run could have hidden the files then; the first run takes root's files as they stand. A rollback to a release from before J-178 reads the claim in the panel's folder and will not find it: claim the stick again (sudo nxlx-usb claim); the migration says so in its log line.
