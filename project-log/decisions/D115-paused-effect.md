## D115. An exact seek of nothing redraws a paused clip on classic mpv (2026-10-31)

Over a paused clip classic mpv answers a new shader list by redrawing its cached picture, which never runs the user shaders, so an effect that went on, changed or came off showed only when the clip played again. After the list is set and the clip is paused, `Player.redraw_paused` sends `seek 0 relative+exact`; the picture is decoded again through the new list and the position does not move. Over a frozen clip the panel's check (`_watch`) no longer waits for a pass time, because mpv gives none for a frozen picture, and answers "unknown" as soon as the pass is listed. The New renderer is left as it is: it already draws its programs the moment they change. Why: it is the smallest command that draws the shown frame again with nothing else changing (a frame step moves the clip by a frame, a step back moves it back and is slower; a snapshot of the screen is not a redraw), and it was seen to work on mpv 0.41 (the Pi's 0.40 and CI's 0.37 are CI's and the node's to show). Cost / rules out: one more command and one more question for every change of the list while paused; a seek decodes from the last keyframe, so a long-GOP clip at 1080p on a Pi 4 may take longer than a frame (unmeasured); a clip that cannot seek (a picture, a live input) is not redrawn until its next frame; an effect over a frozen clip stays "unchecked" in the panel because no time can be read. It rules out faking the cure by changing what the snapshot says.
