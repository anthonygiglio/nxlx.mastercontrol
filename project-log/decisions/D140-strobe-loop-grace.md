## D140. A loop restart or a seek does not take the picture away (2026-11-14)

Effects.picture keeps the picture last read for the item that plays when mpv has no video-params, but only when mpv itself says it is a gap (not idle, and seeking or at the start of the item: time-pos under PICTURE_GRACE, 1 second). Why: at the start of each pass of a short loop mpv has no video-params for a moment, and a Strobe press there was refused with 409 and released. Nothing reads the picture unless an effect is being put or the panel polls, so the read is taken when the item starts: Player.play and fade_to_program tell a listener (on_source, wired by the Api to Effects.note_source) and one bounded look (up to 3 seconds, a tenth apart, on its own thread) reads the picture as soon as the item shows one. The held picture is only that real, fitting read of the same item (path, source epoch and clears), so a path that still names the old file after a load is not taken for the new one, and a clip that never had a fitting picture (an unfit format, a stream with no first frame, a refused pair) is refused as before. No plain picture stands in: it hid unfit formats and generators. The New renderer's stand-in is checked first. vid is not asked: the same item had a picture, and a playlist reload may say "auto". An unreadable time-pos does not count as a start; seeking alone is enough. Cost / rules out: one short look per new source; a source put on by another route than play and fade_to_program has no held picture until something reads it.
