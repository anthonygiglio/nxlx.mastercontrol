## D140. A loop restart or a seek does not take the picture away (2026-11-14)

Effects.picture keeps the picture of the item that plays when mpv has no video-params, but only when mpv itself says it is a gap: a video track is selected (vid is a number), the player is not idle, and it is seeking or at the start of the item (time-pos under PICTURE_GRACE, 1 second). Why: at the start of each pass of a short loop mpv has no video-params for a moment, and a Strobe press there was refused with 409 and released. The first try counted a second from the last read, but nothing reads the picture unless an effect is being put or the panel polls, so a press from MIDI or OSC met a stale read; mpv's own state needs no read. The picture used is the last one read for the same item (path, source epoch and clears, so a path that still says the old file after a load is not taken for the new one), or a plain picture when none was read, which the next read replaces. The New renderer's stand-in is checked first, so a generator never gets the one before it. Cost / rules out: a stop, another file, a source with no video, an idle player and a gap that lasts past the start of the item are refused as before; a plain picture may be wrong for a moment (colour matrix) on a clip nobody had read.
