# Lessons learned

Append new lessons at the bottom. Format: what happened, what we do now.

- **An archive extractor stripped `../evil` as if it were a top folder.** Found by a test. Validate the raw member name before stripping anything.
- **A rotation of 45 degrees was accepted, then the panel reported "player down".** Validate values at the API (only 0, 90, 180, 270), not only in the player.
- **The server dropped connections on unexpected exceptions.** Added a catch-all 500, and made responses tolerate a client that vanished.
- **Compiled `.pyc` files got committed.** Untracked, and a test now guards against it.
- **The installer's uninstall crashed with an empty root variable.** Found only by running the installer for real in a container. Prefix safety guards added. Run installers for real, not only through ShellCheck.
- **Independent reviews found real defects in every risky feature** (the update path, uploads, the network helper): overwrite races, temp-file leaks, state kept in a directory other users could write, an undo that could fail silently. Keep doing a separate, read-only review for anything touching root, the network, uploads or auth, and turn each finding into a test.
- **The browser test caught real UI bugs**: a helper that did not flatten arrays, a long preview widening the page on phones, a sticky tab bar covering controls, a card calling the API while its module was off.
- **A redraw of the System screen wiped the Network form.** It also made the browser test flaky on slower CI runners. The card now keeps its state. When a UI test fails only in CI, look for a redraw or load race before touching assertions.
- **Link checking failed CI on dead legacy hotlinks.** The link check is advisory and excludes known-dead hosts.
- **A cloud session cannot push tags or delete branches** (HTTP 403 from the proxy). Do those from a normal clone or on github.com.
- **A session's GitHub access is fixed to the repo name it started with.** After the rename, start new sessions on the new name; an old session still reaches it through GitHub's redirect.
- **Two legacy images differed only by letter case**, which broke clones on macOS and Windows. Removed the unused one.
- **When the shell tool went down mid-work**, files were backed up to a throwaway branch through the GitHub API before resuming. Commit and push early.
- **Claims must match what was run.** Everything so far ran in a container with a real headless mpv and fakes. Nothing has run on a real Pi, display, USB stick, TouchOSC or NetworkManager. Say so in every summary until that changes.
- **On macOS, pulling the case-collision fix left the surviving image showing as deleted.** #9 removed `01_hdmi_connect.jpg`; on a case-insensitive disk that also removed the file on disk that `01_Hdmi_connect.jpg` maps to. The tracked file was fine; `git checkout -- <path>` restored it. If `git status` shows a lone deletion after such a pull, check for a case-variant removal before assuming damage.
- **`re.match` with a `$` anchor accepts a trailing newline.** A MIDI device path and a schedule time both passed with `\n` on the end. Use `re.fullmatch` for every validation of untrusted text; a test that appends `\n` to a good value catches it.
- **A per-source rate limit means nothing for UDP from private addresses, because the source can be forged and the limiter clears its table when full.** Put a global packet cap and a cap on calls into the player next to it. Also: `apply()` methods that start threads or sockets need one lock, and turning a module off must stop what it started.
- **Read the check list before merging, not only the merge command's exit.** A `while ... pending` wait loop ends on any result, including a failure. Count failures explicitly and stop if there is one.
- **A sandboxed service can silently lose a device the code needs.** MIDI worked in tests and would have failed on the image because the unit hid `/dev`. When a module needs a device, network port or group, check the systemd unit, not only the Python.
- **The intermittent network-form CI failure was real, and diagnostics found it in 6 reruns.** After a redraw the address and prefix came back but the gateway did not: the form kept typed values only through each field's `input` event, and one was lost. The card now copies the values from the page just before any rebuild, and the browser test sets one field without an event to prove it. Lesson: when a UI test fails "only in CI", add a diagnostic that prints the state at failure and rerun until it shows; do not merge over it and do not loosen the assertion.
- **The first boot on real hardware found two service bugs that 20 green CI checks and a container never could.** A systemd ordering cycle silently dropped the player's start job (the only trace: one journal line "Job ... deleted to break ordering cycle"), and mpv's control socket is owner-only regardless of `UMask`. Lessons: test the units, not only the Python (a static check of the ordering graph is cheap); when a first fix "does nothing", look at timing before assuming it is wrong (the hook ran before the new socket existed and fixed the stale one); and read `journalctl -b | grep -i cycle` early when a service is inactive with no log.
- **`RuntimeDirectory=` in two units re-owns the shared directory on every start** (systemd chowns it recursively to the starting unit's user), so file owners in `/run/pvj` change under you. Rely on group and mode, not on the owner name.
- **Measure a performance claim with an A/B run on the real device, and trust the person watching over a counter.** I first measured the live preview as harmless (drops 4.5, 4.0, 0.0 per second in three quick windows, a noisy comparison) and the owner said playback was choppier with it open. Longer alternating windows showed 0.0 without, 4.7 with, and still 1.3 with one snapshot every 5 seconds. Lessons: run at least A, B, A, B, A on a steady source, and remember a drop counter can miss a stall.
- **Defaults that are right on a PC are wrong on a Pi.** mpv's default scalers dropped 15 frames a second scaling 1080p to a 2560x1440 monitor on a Pi 4 (`--profile=fast` cured it), and its default sound output on a Pi is the headphone jack, not HDMI. Both were found only by playing a real film on real hardware.
- **Never join a thread while holding a lock that thread needs.** The MIDI hub's stop joined its reader and scanner threads under its own lock, but both call back into the hub; every shutdown stalled for the 3 second join timeout and then a stray reader started. A test that asserted "switching off takes under 1.5 seconds and leaves no threads" caught it. Collect what to stop under the lock, release, then join.
- **Test a hardening flag with the hostile input, on the real program.** `--load-unsafe-playlists=no` sounds like it stops a fake playlist and did not; an actual fake `.mp4` playlist uploaded to the Pi showed it, and `--access-references=no` did stop it. Also: a review agent's finding is a claim to reproduce, not to accept or dismiss (its "medium, unverified" note said exactly what to try).
- **A review that reads docs against tests finds the cheapest bugs.** The MIDI docs said "your mappings win" while a test asserted "both fire" and a comment agreed; whoever wrote the test had written down the bug.
- **Every sandbox line is a feature someone will need later.** `RestrictAddressFamilies` without `AF_NETLINK` looked safe and silently emptied the Network card on real hardware, because `ip` returned an error that the code treated as "no addresses". When a sandboxed service shells out, run that command under the same sandbox (`systemd-run -p ...`) on the device; and make "no data" distinguishable from "could not read".
- **Run an upgrade over a live install, not only a fresh one.** The new installer logic passed its tests and still aborted on the Pi, because `usermod` refuses while the account has a process running, and a `set -e` script then stops half-way. Test migrations of accounts and ownership on a box that is running the old version.
- **A probe can lie.** A "can the player write here?" check reported YES after the fix because the first run had left its probe file behind, and `touch` on an existing file succeeds. Test with a fresh name, and test the exact attack (replace the file) rather than a stand-in.
- **A line protocol that ends with CR alone hangs `readline()`.** PJLink ends each line with a carriage return and no line feed; `socket.makefile().readline()` waits for `\n`, so the client would have sat out every timeout against a real projector. A fake server written from the spec, not from the client, caught it. Read such protocols byte by byte up to the terminator, with an overall deadline.
- **Check that the thing you measure is running before you trust the number.** The first warp-table benchmark on the Pi showed 0 dropped frames, because mpv had silently refused the shader (it wanted 32-bit floats for a half-float texture) and was drawing the plain picture. Capture the program's own error log (`request_log_messages`) and look at a screenshot of the effect for every variant you time.
- **When a fix changes nothing, the cause is somewhere else.** Steps along diagonal lines of the warped picture survived three precision fixes unchanged. Emulating the table in Python showed the table was exact; the steps were at inner grid lines, where per-cell perspective maps do not agree, and the exact shader had the same break. Grid cells are bilinear now.
- **A settings migration on the test box binds every later deploy to it.** After the sync branch moved the Pi's settings to schema 13, deploying a branch that only knew 12 left the panel refusing to start (correctly: it never touches newer settings) until the newer code went back on. Deploy branches to the box in the order they will merge, or bring master in first.
- **Piping into a command behind `cat pwfile | sudo -S` leaks the password.** On the test Pi, `echo line | S tee -a file` (with `S(){ cat /tmp/.pw | sudo -S "$@"; }`) wrote the sudo password into a world-readable file: sudo was still authorised from the step before, so it did not read stdin, and `tee` got the password instead of the line. Use `sudo -k -S` (always read the password) and never pipe data into a sudo command; stage content in a file and `sudo cp` or `sudo sh -c 'cat f >> g'` it. (2026-10-01; the file was restored within a minute and the owner asked to change the password.)
- **Two claude sessions in one working folder step on each other.** A second session checked out its branch in the shared folder between two commands of the first, so a commit landed on the wrong branch (fixed before it was pushed). The merge-queue script also switches branches in its own worktree, so do not edit there while it runs. Give each session, and each background tool, its own `git worktree`.

- **Reading the standard found bugs that the tests could not.** The PJLink client's answer pattern allowed letters only, so every answer to INF1 and INF2 would have been rejected; the old fake never sent those. The name is UTF-8 and was decoded as ASCII. Read the published document before adding commands, and write the fake from it with section numbers.
- **A background thread turns a mocked lookup into a real connection.** A test mocked the name lookup to return 192.168.0.7 and only meant to check a lock; once a background check existed, it carried on and connected to that address on the real network. When adding a background worker, grep the tests for every place the feature is switched on with a non-loopback address, and give those tests a connect that refuses.
- **A log call nobody ran.** `self.log(...)` in the background projector path pointed at a method the API never had; it only runs when a projector fails in the background, so the thread died silently. Test the failure branch of anything that runs in a thread.
- **"Next due = now + interval" after the work overwrites a request made during the work.** A refresh asked for while a status check was running was lost for a whole interval. Mark the timer as "running" before the work and only set the next time if nobody changed it meanwhile; test it with a check that blocks on an event.
- **Check-then-send needs one lock around both.** The input retry looked at "is this still the pending choice" only after it had sent, so a retry already on its way overrode a newer choice. A test that counted commands "at most 2" could not see it; the test that found it blocks the send on an event, makes the newer choice, then releases. When two paths can send the same kind of command, put "is it still wanted" and the send under one lock, and write the test that holds one path in the gap.
- **A stop signal that is only looked at between loops is not a stop.** A stopped worker finished its whole list of six questions and then saved the answers with the module off. Check the signal before every command and before every save, and count threads with `threading.enumerate()`, not with the object's own list of what it thinks is running.
- **Do not reuse a control for a second job.** The label field read the input chooser, whose change event switches the projector; naming an input switched to it. One control, one effect.
- **A test with `--vo=null` proves nothing about a shader.** The null output never compiles one, so "no error in the log" passes whatever the file holds. A CI step with xvfb, Mesa and `--vo=gpu --gpu-context=x11egl` makes mpv draw for real (run it with `--opengl-es=yes`, the stricter language, and without: on the Pi 4 mpv made a desktop OpenGL 3.1 context with GLSL 1.40, not OpenGL ES, so the first note here, that a Pi uses the ES language, was a guess that the first hardware run corrected); check the picture through a screenshot, and make a skipped test fail the step (unittest exits 0 when everything was skipped).
- **Spike the facts before the design.** Three short CI runs settled what no reading had: mpv applies brightness before the MAIN hook (a generator there cannot be faded or blacked out; hook NATIVE over an RGB source), a medium-precision value above 65504 draws black on OpenGL ES with no error, and mpv reports a refused shader text only once and lists its pass with a time of 0.
- **Two users of one fader cancel each other.** The panel's Fader keeps a play that waits for its dip as a callback, and every other ramp or cancel drops it: Vibes used it and the operator's clip was accepted and never played. A background feature gets its own fade, and "something else was played" must become true when the play is accepted, not when it loads. The test that missed it called the fake player directly; the test that finds it goes through the real API with the real Fader.
- **Check the text the compiler reads, not the text the user wrote.** Line-anchored checks were bypassed with `/**/#extension`, a declaration in the middle of a line, and letter case. Strip comments and refuse continuations first, then check, and pass on only what was checked.
- **`json.loads` accepts NaN, Infinity, 400-digit integers and repeated keys.** Each one either raised an exception nobody caught or let an unchecked value win. Use `parse_constant` and `object_pairs_hook`, and catch everything around a parser that reads files a person may have put there by hand, so one bad file cannot take a list down.
- **A lock held across a sleep is a queue.** Vibes held its one lock through its dip and the wait for the GPU, so the second OSC cue waited and every cue behind it too. Requests set fields under a short lock; slow work has its own lock that nobody waits for.
- **When an assertion is flaky, assert the claim instead of loosening it.** A screenshot of the test clip was sometimes one flat colour on the CI rig; the claim was "the shader is gone", and that can be asserted directly.
- **A test's name is not what it asserts.** `test_default_export_holds_no_secret` asserted that the RTMP stream key was in the export. When a review names a secret, grep the tests for the sentinel and read which way each assertion points.
- **A deny-list of secret names misses the next name.** `passphrase`, `password`, `token` were listed; `auth`, `sign`, `pwd`, `wsSecret`, a percent-encoded `pass%70hrase` and an SRT streamid with `u=` were not. Where the set of harmless names is small and known (SRT options), list those instead, and compare names after decoding.
- **Cut after scrubbing, never before.** Log lines were cut to 400 characters and then scrubbed; a login that straddled the cut lost its "@" and kept its user name. Test it with a secret the box does not know, or the known-secret pass hides the bug.
- **Migrating an imported file adds defaults that then look like the file's word.** A schema 9 file had no projectors; the migration added an empty list and the import wiped the box's own. Note which sections a file holds before migrating it.
- **Two rules for one thing drift.** `redact` (panel) and `strip_login` (export) each decided what is secret in an address, and disagreed about the passphrase. One function, two renderings.
- **Clearing access in steps leaves a gap for a request already past its token check.** Cancel codes, then wipe devices, then rotate the PIN let another device's request land in between. Do it under the locks those requests take, and have the late request check that its device still exists after it acts. The two auth locks were also taken in opposite orders by `pair()` and `rotate_pin()`; one order everywhere.
- **Merging a feature with background threads changes what a test's fixture data does.** After PJLink phase 1 merged, box care had to match the background projector checks to the settings after an import; the test settings hold 192.168 addresses, so as a precaution (it was not seen to connect) the box care tests replace the monitor's `apply` and assert it was called.
- **A card that redraws on a timer or on an answer must read its form first, and a test must not move on before the answer is drawn.** The Sync card put the saved column back between a choice and the Save click (the Network form's bug again, in a card written later). The server log gave it away: the save that should have been refused answered 200. And a wall-clock limit proves little on a shared runner: hold the thing for much longer than the limit and assert the call returned while it was still held.

## A root helper's sandbox decides what it can do, and a fake runner never sees it (2026-10-04)

The Wi-Fi code wrote its keyfile under `/etc/NetworkManager/system-connections`, and every test passed, because the tests run the helper with a fake nmcli in a temporary folder. On a box `pvj-netd` runs with `ProtectSystem=strict`, so `/etc` is read-only to it and every Wi-Fi join would have failed and reverted. The independent review caught it by reading the unit file. `tests/test_units.py` now checks that the helper may write to `netcfg.KEYFILE_DIR`. Whenever a helper writes to a new place, or opens a new kind of socket, check its unit file and add a test that ties the two together. The same review found that `RestrictAddressFamilies=AF_UNIX` had always kept `ip -j addr` from working in the helper, so its own overlap check never ran on a box (the panel's did).

## An undo must never be dropped because one command was slow (2026-10-04)

`_attempt_revert` asked nmcli whether the candidate existed inside the `try` meant for a bad saved connection id. A single nmcli timeout there deleted the saved state and forgot the undo, leaving an unconfirmed network up with no timer. Only a bad saved id is a reason to give up planning; anything nmcli does is a failed try. And after many failed tries the helper used to forget the job too, which let a new change overwrite the saved state; now it keeps trying once a minute and refuses new changes until the undo has worked.

## A card that asks the server while it is being built (2026-10-04)

The Updates card called `refresh()` while it was being built, and `refresh()` does nothing until the card is on the page. On the old single System screen a later redraw hid this; with one page per item there was no later redraw, so the card stayed at "Loading..." and the browser test timed out at `#updateversion`. A card that checks `isConnected` must start its first request after it is attached (`setTimeout(refresh, 0)`).

## A switch built on an API that saves a whole section (2026-10-04)

`POST /api/schedule` replaces the whole schedule: `entries` left out means no entries. A page switch that sent only `enabled`, or entries the panel had read some minutes earlier, would have wiped or rolled back the schedule. The DMX toggle had the opposite fault: it sent every field on the page along with the flag, so switching on also saved a half-typed universe. Before a control is folded into a switch, read the handler: send exactly the flag where the handler merges (DMX, MIDI, OSC, Remote support), and where it replaces, read the saved state just before the change and send that back unchanged.

- **A note that says "this background retry is ours" must be cleared only by whoever stops the retry.** The room marked an input change that the Projector module was retrying for it; the generic "step ended" path cleared the mark, so when the module was switched off the retry carried on with nobody left to stop it. One run in ten showed it. Clear such a mark in one place, after the stop, and test "switch it off in the middle" many times over.
- **Cancelling on every tap means the first command goes out after the last tap.** A test that tapped twenty times and then moved the fake projector on failed one run in four: the power-on had not been sent yet. In a test, wait for the state the next step needs, not for the request to return; in the design, remember that a stream of taps holds the commands back.
- **A guard test that fails on purpose is worth its noise.** Box care's "every settings section is checked or never exported" failed the moment the `room` section met it, and a second guard asked for a bad value per section. Both took minutes to satisfy and would have been a silent hole otherwise. When a branch adds a top-level settings key, add it to the defaults so those guards see it.
- **Keep a new screen's code out of the shared file and its hooks away from other branches' lines.** The Room screen is its own script that borrows the panel's helpers; the hooks in `app.js`, `scheduler.py`, `midi.py` and `osc.py` were put on lines of their own, a few lines from where two open branches had changed things. Merging master with both of them in produced one conflict, two adjacent lines in `Api.__init__`.
- **A remembered status is not an answer.** The room took "cooling down" from the status cache as proof that Off had worked, a moment after the projector had in fact started warming up; it reported "off" and the projector stayed on. When a decision depends on the device's state, ask the device at that moment; use the cache only for what is shown.
- **"One sender" is only true for the paths you count.** The room had one thread per projector and still let an older source follow a newer one, because the Projectors card sends too. The check "is this still wanted" has to sit inside the lock both senders share, just before the send.
- **A confirm that appears under the finger is confirmed by a double tap.** Put the question where the second tap cannot answer it, or do not take an answer in the first half second.
- **Read the source for what a counter counts before building on it.** The shader notes said mpv's `frame` counts every drawn frame and that a redraw adds one. In mpv's source it is `frames_uploaded`: every picture uploaded since the player started, clips included, redraws not. Nothing outside the shader can read it, which decided how the speed control had to be built (the carrier counts its own frames).
- **A helper picture that nobody was meant to see becomes visible on the error path.** Painting the carrier with its frame number was invisible in every normal test; CI's real mpv showed it after a refused shader with nothing to go back to: dark red where black was promised. When a hidden layer changes, walk every path that takes the layer above it away.
- **The first hardware run corrects the guesses, so write guesses as guesses.** A Pi was said to use the stricter ES shader language; mpv made a desktop OpenGL 3.1 context there. Two shaders marked "low" by counting sines were medium by the clock. The cost table is now the measured one, and what is still a guess (a Pi 5, x86, the guard's thresholds) says so.
- **Work that is put off must carry the moment it was asked for.** The step and preset jobs were handed to a worker without the player's epoch; 0.2 seconds later they took the screen from a clip, undid a Stop and ended a rotation. Every other path checked the epoch; the two new ones that were deferred did not. A deferred action is a new way onto the screen and needs the same check as the direct ones.
- **A detector that punishes must be able to tell its subject from its surroundings.** The guard blamed the shader for every dropped frame, so a box that dropped frames for any reason lost its whole library, permanently. Two failures in a row with no success between are evidence about the box.
- **A request that a controller sends 50 times a second must not do the work.** It checks and notes the wish; one worker does the slow part at its own pace with the newest wish. The same shape keeps a MIDI reader thread, a slider and the schedule from waiting for the GPU.
- **A repository's licence is where the licence question starts, not where it ends.** ISF-Files is MIT, and nine of the 36 generators the box can run carry a comment that their code comes from somewhere else (a book with its own terms, a deleted repository, Stack Overflow, a font). Read every candidate file's comments and credit before bundling, follow each pointer, and leave out what cannot be settled; write down which and why, so the owner can decide.
- **Run the real collection before believing a translator.** The translator had only seen files written for its tests; on Vidvox's library it took 17 generators, and 19 more were refused for three reasons no test had: a variable called `out_color`, an input called `color`, and a dash or an arrow in a comment. A survey script that runs every file and counts the reasons found all three in a minute.
- **"It translates" and "it draws" are far apart, and so are the two OpenGLs.** Of 27 files that translated, CI's real player refused five on OpenGL ES that desktop OpenGL took (a function named `sign` or `round`, a float compared with a whole number), two drew black, and eleven drew what they should: two colours. Make the GPU test try every file and report all of them in one run, with a line per file in the log; a test that stops at the first failure costs a CI round per file.
- **A file name with a space is a release bug waiting.** `tools/make-release.sh` hands git's file list to tar split at white space; upstream's "Simplex Noise.fs" would have broken the bundle, and the licence test split names the same way. Shipped files have no white space in their names (a test says so).
- **A test that looks for a secret by its digits will one day find them in a number.** `test_no_secret_is_in_it` failed once on this Mac because the PIN "4821" appeared inside the disk's byte count (482138402816). Not fixed here (it is not this branch's code); pick secrets for tests that cannot occur in a counter.
- **Many agents at once is slower than two.** On 2026-10-03 and 04 three or four background agents ran together and the usage limit stopped all of them four times, each time mid-task; one lost everything because it had pushed nothing, and a measuring run left a shader on the owner's screen for almost eight hours. Run one or two, open the pull request after the first commit, push after every step, and write down where each one is before the limit can hit.
- **A fact about the hardware that was only assumed.** The docs and a lesson said a Pi runs shaders through OpenGL ES; the first look at mpv's log on the Pi showed a desktop OpenGL 3.1 context. Read the program's own log on the device before writing down which path it uses.
- **A folder that systemd hands out belongs to one unit, or to none.** Three units with different users named the same `RuntimeDirectory`, and systemd gave the folder, with a root helper's socket and the PIN in it, to whichever started last; the earlier lesson here ("rely on group and mode, not on the owner name") accepted that instead of asking who could then replace what. It was seen by listing owners on the real Pi after a restart from the panel, not by any test. Now a static test refuses a shared, group-writable or nested-parent RuntimeDirectory. When a root helper's socket is in a folder, ask who can rename the folder and who can unlink in it, on the box, after each kind of restart (`find /run/pvj -printf '%u:%g %m %p\n'`).
- **Changing where a socket lives is a change to every release that can run under the same units.** The update path restarts only the player and the panel, so a moved helper would have been unreachable until a reboot; and a rollback runs the older code under the newer unit files, because a release holds `pvj/` and `bin/` but not `install/`. Give an environment variable one meaning that old and new code both survive ("the folder this process writes"), add new names for anything else, and test the older code's view explicitly.
- **Root must not write, chown or chmod a name inside a folder an unprivileged account owns, and `[ ! -e ]` is true for a dangling link.** The installer copied a small note into the panel's folder "safely" (checked it was not a link, checked the target did not exist); the review planted a dangling link and root created its target. Do not carry such things over at all; where root must make something for a service, make it in a folder that is root's.
- **A sandbox turns "permission denied" into "read-only file system", and the kernel checks the mount first.** `unlink` in a folder the unit mounts read-only fails with EROFS, not EACCES; the code caught PermissionError and the test imitated the box with `chmod`, so every preview on a box would have been a 503. When code runs under `ProtectSystem=strict`, do not attempt writes outside its own folder at all, test the errno the sandbox really gives, and run the request once inside the real unit (the `real-install` CI job, the checklist's R3b).
- **"Is the migration done?" must be answered by something written last, not by a side effect of its first step.** The installer recognised the old layout by the owner and mode of the folder, which its own first two commands changed; an interruption after them made the next run think it had finished. Write a marker at the end, remove it at the start, and check what is actually there on every run.
- **"Nothing new is needed there" is a claim to test, not to repeat.** The brief for the projector Edit said settings export and import needed nothing and asked for a round-trip test anyway. The test failed at once: an edit to a new address leaves input names without an input list, and the import refused its own box's export. Whenever a change makes a new state the settings can be in, export it and import it in a test.
- **When one route serves two roles, the route table is not the check.** Lowering `/api/access/*` from full to live would have given a presenter everything on those routes. Each handler now decides per action, a refusal is a 403 and never a quiet narrowing, and the tests list every action a presenter must not get. The same goes for a display that one request replaces: "may show the guest code" also had to mean "may not replace or prolong the owner's PIN", and that is decided under the display's own lock.
- **"That was already possible" is not a bound.** The first D48 waved the unlimited device list through because a guest code holder could already add 20 devices. The review looped it: a presenter, new code, 20 pairs, 200 devices in 0.3 seconds. When a change widens who can reach something, count what one holder of that access can do in a loop, and put a number on it.
- **A secret must not ride in an address, not even as a cache-buster.** A first draft asked for the QR picture with the join code as its "changed" marker; the request line, code included, would have gone to the service log. The picture now carries a number, and the browser test checks the code is not in the address.
- **The manufacturer's guide may not hold the number you need.** The brief said "get the factory MIDI assignments from the Korg parameter guide". The guide (an encrypted PDF, read with forty lines of standard-library Python because no PDF tool is installed here) describes every parameter and prints no factory value; Akai's pages give none either. Read the document before promising what it confirms, name the secondary source that was used instead, and mark the data unverified in the file itself, not only in the pull request.
- **An ALSA card id is the last word of a product name.** "Launchpad Mini" is `Mini`, "MIDI Mix" is `Mix`, and a Launchkey Mini is `Mini` too. Anything that acts on a controller by its card id alone (a profile, and one day lights) can hit the wrong product; check the product name as well.
- **A default map and a real controller overlap.** The built-in map's CC 20 to 25 are inside the nanoKONTROL2's knobs and the MIDI Mix's knobs. A new layer under "the person's mapping" has to say what happens to every layer below it, with a test on the exact numbers that collide.
- **A shader text must be written for the strictest of the compilers that will read it.** A variable called `half` compiles on desktop OpenGL and is refused on OpenGL ES, where it is a reserved word (as are `fixed`, `sample`, `filter`, `input`, `output` and more: the list in `RESERVED` in `pvj/shaders.py` is the one to check a name against). It was caught before the push only because the shaders were first compiled in a browser's WebGL 1, the strictest dialect at hand. Compile there first; CI stays the judge.
- **A picture that is judged by one screenshot has to be a good picture at every moment.** The GPU test takes one frame at a time nobody chose. A strobe caught between flashes, a chase with its lit bar off the screen, a beam that points away: each would have been a dark or flat picture in CI now and then, and a red check that comes and goes. So every flashing shader dims to a floor instead of going black, and every graphic one carries a soft shade so that two flat colours are never the whole picture. The same rule is what a room needs.
- **A shader has no memory, so a rate cannot be ridden smoothly.** Its motion is `TIME * rate`; when the rate changes, the whole product changes, and the picture jumps to another place in its cycle (after an hour, a change of 1 percent is many cycles). For beats that is not seen; for a tunnel or a turning wheel it is a jump at the moment the slider is let go. Only an engine that keeps the phase and hands it to the shader can cure it (the speed control of the shader-engine branch does that for the common speed, not for a shader's own rate).
- **A count that is written in twelve places is twelve red checks.** "Ten bundled shaders" stood as a bare 10 in three test files, five times in the browser test alone, and each was found by one CI run. The set is now named file by file in one list, and the browser test has one constant.
- **A headless browser makes a usable eye for shaders on a machine with no GPU test rig.** Edge with `--headless=new --enable-unsafe-swiftshader --dump-dom` draws WebGL without a display; the page renders every variant, measures it and writes the numbers and a contact sheet into its own text. It printed the page and then never exited: read its output from a file and stop it, do not wait for it.
- **A page that polls must know which controls are in someone's hand (2026-10-04).** The first Shaders page put its values into the shape of the controls card, so every poll rebuilt the sliders, and it skipped the redraw only while a range or a list had focus: an XY pad, a colour picker and a name field would have been wiped mid-use. Split what a card is made of from the values in it: rebuild on the first, patch the second, and ask each control whether it is free (not held, nothing waiting to send, nothing just sent) before giving it the box's value. A control that was refused keeps its note through the next redraw, so the note has to go by itself.
- **Count things the way the box counts them (2026-10-04).** "Knob 3" is the third input a controller can drive (numbers, switches, choices, events), not the third control on the page: colours and points are drawn too and have no knob. Preset 3 is the third in the box's list, "default" included. The page takes both orders from the API's own rule and shows the number on the button, so the key, the pad and the label agree.
- **No mpv and no Playwright on the Mac, and no installing (2026-10-04).** The browser test needs both. What was there: Microsoft Edge and Node. A scratch script outside the repository ran the panel against the tests' fake player (`tests/test_shaders.SourcePlayer`) and drove Edge over the DevTools protocol with Node's own WebSocket: enough to see screenshots and check requests before pushing, with CI as the real run. Worth keeping in mind before waiting ten minutes per CI round.

- **A layer that is removed must not uncover the layer below it for traffic still in flight.** Unplugging or switching off cleared a controller's layout while its reader could still deliver a message, which then fell through to the built-in map (CC 20 is opacity there). Stop the source first, drop what is still on its way, and remove the layer last.
- **A check that cannot look must not be read as a check that passed.** The product-name check returned "unknown" both for "no card list" and for "a name I could not use", and unknown meant "match by id". Keep the two apart, and prefer an identifier the device cannot choose freely (the USB id) over a name.
- **A question in place needs the card to stand still (2026-10-04).** `confirmRow` hides the tapped button's row and puts the question after it. A card that redraws on a timer (projectors every 5 seconds, sync every 2, updates, support, network) wipes it, and the person's "yes" lands on nothing. Every such card now asks `asking(body)` before it redraws. And the row it hides is `closest('.row')`: a button that sits directly in a card hides the whole card, so every button that can ask is wrapped in a row of its own.

- **An `<img>` cannot tell a 409 from a 503.** Its error event carries no status. To say "nothing is on the screen" apart from "the player is not running", the picture is asked for with `fetch` and shown from a `data:` address, since the policy has no `blob:` for pictures.

- **A count of sines is not a cost (2026-10-05).** Thirty shaders were written "to stay at or under nxlx-ember" by counting operations per pixel and all but one were labelled low. On the Pi 4 eight were medium, and nxlx-lantern took 20.5 ms at 720 lines, nearly twice nxlx-ember: divisions, square roots and a loop over three or four objects for every pixel are what the count did not see. Label a shader's cost only after it has run on the board; until then say "not measured".
- **How many frames a board drops depends on the screen's refresh rate, not only on the GPU (2026-10-05).** 30 pictures a second on a 75 Hz screen get two and three refreshes in turn, so the budget for a picture is 26.7 ms, not 33.3, and a pass just under the budget drops frames in bursts with clean seconds between. A 20 second window put several shaders on the wrong side of a line; 80 seconds moved three of them. Measure near a limit for a minute or more, name the screen with every number, and do not carry the numbers to a 60 Hz projector unmeasured.
- **A check that needs six bad seconds in a row misses a fault that comes in bursts (2026-10-05).** The guard marked what dropped 7 to 11 frames a second within 9 seconds and never marked nxlx-lantern, which dropped 3.8 a second on average and up to 8: one good second started the count again, and how often the guard was asked changed its answer. Judge a rate over the whole window.
- **Leave a dead-man's switch on a box you measure from far away (2026-10-05).** The Mac's disk ran full in the middle of the run and for some minutes no command could be started, with the Pi at another picture detail, a temporary device paired and a script's files in `/tmp`. From then on a small root process on the Pi held a deadline in a file and would have put everything back, revoked the device and removed the files, itself included, had nobody moved the deadline. Start it before the first change, not after the first fright.
- **"Put it back as found" has a limit where a service migrates its settings on the first save (2026-10-05).** The first change of the picture detail made the panel write the shader settings in the engine's form (the two sets written out). The values were restored through the API and compare equal; the file's form cannot be restored without restarting the panel, which the run was not allowed to do. Read how a setting is saved before changing it on someone's box, and say in the report what could not be undone.
- **A wait that looks for its own words finds itself (2026-10-05).** `pgrep -f "script.py"` inside an ssh command matched the shell that ran it, so the loop never ended; `pkill -f` with the same pattern killed its own session; and a `grep _end` for an end marker matched a field called `temp_c_start_end_max` at the first line. Match a pid, or a marker that cannot occur by accident.

- **A staged password file was there and empty (2026-10-04).** The owner typed the staging line on a phone, the password did not arrive, and `/tmp/.pw` was made with nothing in it. `test -f` said yes; `sudo -S` then failed in a way that looked like a wrong password. Check a secret that someone else staged with `test -s` (it exists and is not empty) before using it, and say "the file is empty" instead of trying again.
- **A device policy with only "r" did not mean "cannot make a sound" (2026-10-04).** `DeviceAllow=char-alsa r` was read for months as "the panel can only read MIDI". The device policy only bars `open()` for writing; ALSA's mixer and PCM work through ioctls, and `sound/core/control.c` and `pcm_native.c` (v6.12, fetched whole and searched) never look at the open mode; the account is in `audio`. A first answer came from a tool that summarises a fetched page; it was right, but a 100 KB file may be cut short there, so the files were fetched and searched before the claim went into the decision. Only rawmidi output really needed the `w`. When a sandbox line is the argument, ask what the device does with a read-only handle before writing down what the line prevents.
- **"A unit file does not travel with an update" was written down and was wrong (2026-10-04).** D49 and MIDI.md said so; `pvj/update.py` runs the installer, which writes every unit and reloads systemd. It was true only of a copy of the files by hand. A claim about what a deploy carries is checked by reading the deploy, each time.
- **`dict(a, **b)` only takes string keys (2026-10-04).** The lights writer overlays one table on another and its keys are bytes; `dict(want, **over)` raised a TypeError on a thread, the writer ended, and the test only said "condition not met". `{**a, **b}` takes any key. A thread that can die needs its reason where a test prints it.
- **Three PDFs from three makers and no text came out (2026-10-04).** The fetch tool could not read them, the dev Mac has no PDF tool, and a hand-made extractor got only the tables (the body text uses the fonts' own letter codes). The Launchpad's tables were enough to confirm the layout; the formula had to come from a search engine's quotation of the same PDF. Say in the docs how a source was read, not only which source.
- **A match that is good enough to read is not good enough to write (2026-10-05).** The profile match has a fallback for when the card list cannot be read: the card id alone decides. That was a fair choice for input (the worst case is a wrong drawing) and it was reused, without a second look, as the gate for opening a device for writing, where the worst case is eighty note-ons into someone's synthesiser. The review found it by making the describer fail. When an existing check becomes the gate for a stronger action, ask what its weakest "yes" is.
- **"Read it online and cite it" was answered with a search engine's quotation, and one number was not in the document (2026-10-05).** "400 messages a second" came from a search summary of the Launchpad PDF, went into the profile, the docs and the decision, and the reviewer, who read the PDF, did not find it. The Mac's own PDF library could have read the file. A number is cited from the page it was seen on, or it is left out.
- **A thread that is given up on after a join with a timeout is still running (2026-10-05).** `_stop_all` joined the lights loop for three seconds, forgot it, and `apply()` cleared the shared stop flag and started another; the first carried on. A loop that can be replaced needs its own stop signal, not the owner's.
- **Four Figma calls were enough for a whole style, because the first one was the page's metadata (2026-10-04).** With about five connector calls left in the month, one `get_metadata` on the page (`0:1`) came back as 200 KB of layer names, and in this file the name of a text layer is its text: every hex value, the rationale and the layout of all four screens were in that one answer, saved to disk and read with a script. The three calls left went to the spec board and two screens for the weights, sizes and borders. Plan the calls before the first one, and read the metadata file with a script, not by eye.
- **A check written for one look found a fault of the other (2026-10-04).** `.ctl` is defined twice in `app.css`, for a MIDI controller's cells and for a shader's controls, so in the default look a shader's control also gets the cell's border, background and centred 11 px text. It was seen only when Signal restyled the cells and the sliders turned into boxes. It was first left as it was and undone only inside the Signal block; after the review it was fixed for both looks by letting each set of rules name its own (`.ctlgrid .ctl` for a cell, `div.ctl` for a shader's control), with the cell's padding and top rule written out as what it had always drawn, so the cells did not move by a pixel and only the shader controls lost the box.
- **`$` in a Python pattern lets a trailing newline through (2026-10-04).** The first style check used `re.match` with a pattern ending in `$`, and the test value `"signal\n"` passed it. Nothing was reachable through it, because the name is then looked up in a fixed list, but a validator must say what it means: `fullmatch`. When a fault of a kind is found, look for every other use of the same call in the file in the same change.
- **A headless browser on the dev Mac is enough to look at CSS (2026-10-04).** There is no Playwright and no mpv here, so the harness cannot run, but Edge with `--headless=new --screenshot` on a static page that inlines the real `app.css`, the theme's variables and the fonts as data showed the switch, the slider and the chips in a minute, where a CI round is ten. Two cautions: the process does not exit by itself after the screenshot (wait for the file, then kill it), and its profile folder grew to 380 MB in one run on a disk that is nearly full (give it a folder in the scratch directory and delete it at once).

On master a damaged theme entry broke only `/theme.css` and the panel still loaded unstyled; with the change `GET /` dropped the connection. Found by the independent review, not by any test of mine: the tests only stored themes the API had accepted. Anything on the path of `/` reads settings through a function that answers with the default for every shape (not an object, a name that is not text, a theme that is gone), and the test feeds it those shapes.
- **Green and looked at is still not as staff see it (2026-10-05).** The first Room pictures in Signal showed an unconfigured Room: the set-up form and the built-in "Everything" card. The step that should have made groups was skipped because "Everything" already counted as a group card. A picture or a check of a screen needs the screen in the state its users have it in, made through the API before the check, and the check must say what it expected to find on it (two named groups, labelled source buttons, a result line), or it passes on an empty room.
- **Build the looker before the theory (2026-10-05).** Twelve effect tests failed at once on CI's real mpv, with black screenshots, and two rounds went into theories (frame drops, then the buffer format) that each explained some of it. A throwaway job that played clips in the tests' own order and printed what the player said at every look (the picture's brightness and colours, its position, its dropped frames, its passes, and its own log around the first black look) found the cause in one run each time. When many unrelated assertions fail together, suspect the rig, and make it talk.
- **On mpv 0.37 with Mesa's software GPU and mpv's default scalers, a video played after one of another size is drawn black until a shader goes on or off (2026-10-05).** Seen with a 320 x 180 video after a 160 x 90 one, with and without any shader of ours; with the cheap scaling of `--profile=fast` it does not happen. This is very likely the "flat colour" that the generators' clip test could not explain (`tests/test_shaders_gpu.py`). The effect tests start with their own picture and scale as a Pi 4 does. Whether a real GPU on x86 or a Pi 5 does the same is not known: look for it there.
- **A test picture must be cheaper than the thing under test (2026-10-05).** The first still picture for the effect tests was worked out by `geq` for every frame; the player fell behind, and one measurement came out five times too fast. One frame through `geq` and then the `loop` filter costs nothing.
- **A screenshot is the renderer run again, not the screen (2026-10-05).** mpv's window screenshot draws the current frame once more through the whole pipeline. It shows what a redraw would show, and says nothing about what was on the display at that moment. Wait for a few new frames after a change before looking, and do not write "the screen was never black" from screenshots alone.
- **Ask the output, not the decoder, what the picture is (2026-10-05).** `video-params` named a clip's own range and matrix while the picture was still being drawn with those of the clip before it (same size, same format, played one after the other); `video-out-params` said what the renderer was using, and a text made from it inverted the picture rightly every time. - **"#line n" means two things (2026-10-05).** On OpenGL ES and from GLSL 3.30 on, the next line is n; before that (GLSL 1.40, what mpv makes on a Raspberry Pi 4) it is n + 1. So the line a generator's refusal names has been one too high on the Pi's path since the first version, and no test looked there. An effect's text picks the number by the language version; the generators' text is not changed here.
- **A grid with an even step sees every other line only (2026-10-05).** Interlace Mirror, which mirrors every other line, came out "unchanged" because every point looked at lay on a line it leaves alone. Use an odd step.
- **A pack file's own defaults can be "do nothing" (2026-10-05).** Nine of the 32 filters change nothing until a control is moved (a level at 1, a zoom of 1). "Differs from the picture at its defaults" is the wrong test for them: the test names them, checks that their defaults give the picture back, and judges them on values written there on purpose.
- **Test the rule from the empty state too (2026-10-05).** Every test of "what was asked for before the screen changed hands is dropped" began with an effect on, and the one case that broke the rule began with none: an Off with nothing to take off changed nothing, so nothing was invalidated. A rule about order needs a test from each state it can start in.
- **A count that guesses is not a limit (2026-10-05).** The first estimate of a filter's work read loop bounds with patterns and counted what it could not read as "32, unsure". A limit on uploads built on it stopped nothing that was written to get past it. Refuse what cannot be counted, and then run the strict rule against a few hundred real files before believing it: the first strict version turned away four honest forms that the upstream library uses.
- **I read a file and did not recognise a snippet the reviewer knew (2026-10-05).** The pack's rule is "no well-known snippet without a credit", and it is only as good as the reader's memory of other people's shader libraries. Two files credited "by VIDVOX" match the Geeks3D library almost line for line. A second reader is part of that rule, and "credited to the repository's owner" proves nothing by itself.
- **A time-driven test picture can be out of sight (2026-10-05).** fx-ring at its defaults was unchanged in CI in all three ways of drawing: for part of its cycle the ring was outside the picture. A filter that moves by itself must show something at every moment of its cycle, or the test that judges it has to hold its clock still.

One more pass through the GPU rounds differently: up to 3 of 255 for ordinary video in 16-bit buffers, nothing in 8-bit ones. The limit is now what the pipeline gives, with the reason beside it; a wrong matrix or a shifted picture is far outside it.

## A counter that starts again, and a snapshot that draws its own picture (2026-10-05, effects on the Pi 4)

- **mpv's `frame-drop-count` goes back to 0 each time a clip loops.** The first windows of the effects run were the difference of two readings 15 seconds apart over a 20 second clip; one filter "dropped" minus 1.9 frames a second, and the others were wrong by amounts nobody would have noticed. The generators' runs never met it because their carrier does not loop. A counter read across a window is read every second and only its rises are added; and the guard, which treats a fall as a new start, can never fill its 6 second window over a clip shorter than that.
- **A screenshot is not the screen.** mpv redraws a paused picture from its cached output and runs no user shader until the next frame, but a window screenshot renders the frame anew with the shaders that are set. Every frozen-clip check of an effect, in CI and on the Pi, was a screenshot and showed the effect; the player's own list of passes (`vo-passes`: "redraw cached frame", no pass of the effect) says the display had not drawn it. For anything about what is on the screen while nothing new is being drawn, ask the player what it drew, or look.
- **A count from a shader's text did not predict its cost, again.** For the generators seven of thirty were a class off. For the filters the count's "light" ones took 8 to 21 ms and its "medium" ones 12 to 30 at 1080 lines, and the fixed cost of having any effect on (8 ms at 1080 lines) was larger than the difference between most filters. The count stays as the bound it is for an upload; the word a person reads comes from the table.
- **On a board at its limit the size of the picture decides.** All 37 filters landed in the same place: fine over 720p, too much over 1080p, fine over 1080p at half size. One number per filter would have hidden that; measuring two sizes and the half-size switch for every filter showed it in the first twenty minutes.
- **`pkill -f name` over SSH kills the shell that carries the command**, because the pattern is in that shell's own command line (`[n]ame` does not help when the name appears again later in the line). Twice the measuring run was killed by its own restart command and nothing after the `pkill` ran. Anchor the pattern (`^python3 /tmp/...`) or put the command in a script file.
- **Somebody may walk up to a box that is being measured.** At 13:07 the owner's laptop opened the panel, tried Next and a slider, and pressed Stop; the script went on measuring a stopped player for three minutes and wrote plausible rows (pass times from the last frame, GPU busy 0). A measuring script checks before each case that what it started is still playing, and stops for good when it is not: a Stop from a person outranks the plan.
- **Read what a cleanup deletes.** I removed a pattern of snapshots from the box after copying an earlier, smaller set, and lost two pictures that then could not be retaken.
- **Take the pictures before changing what they show (2026-10-05).** The first commit of the Signal pass over every page changed nothing but the screenshots job. Fifty pictures of the look as it was named a dozen faults in an hour that no check had: a title cut inside a word, sentences in capitals, buttons touching. And the job that takes the pictures used to be skipped when the browser test failed, which is exactly when they are wanted; it runs then too now.
- **`overflow-wrap: anywhere` hides a cut word from a width check (2026-10-05).** With it a flex child may shrink below its longest word, so "PROJECTORS" beside a switch became "PROJECTOR" and "S" and nothing overflowed: `scrollWidth` equalled `clientWidth`. `break-word` with `min-width: min-content` makes the neighbour go to the next line first. The check that finds it measures the longest word of every text in capitals against the room it has, not only of buttons.
- **A list with no gap only looks right while every child is a ruled row (2026-10-05).** `.list` has no gap in the default look because its items carry a rule and padding. Cards that put buttons, fields and hints straight into a list (the mapping card, the codes) ran together once the look took the card's box away. A style that removes a container's box has to give the space back.
- **A stylesheet can say a state the page only has as a sentence (2026-10-05).** The projector row's chip is `::after` on the name with its word chosen by `data-power` on the row: one attribute as the hook, nothing new in the default look. The cost is that the words live in the stylesheet, and a pseudo-element is not read by the contrast check or by a screen reader, so the row's own line must keep saying it.
- **The installed browser is enough to look at the panel on the dev Mac (2026-10-05).** `npm install playwright` with `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1` is 18 MB, and `CHROMIUM=` pointed at the Edge already on the machine drives the harness. Without mpv nothing plays, but nearly every page draws, in seconds instead of a CI round; `ONLY='signal-(room|live)'` on `tests/ui/screenshots.js` takes just those pictures. CI stays the judge.
- **A check of something the box moves must look twice (2026-10-05).** The Signal pass asked that a slider's fill is where its value is. The position bar of a playing clip jumps once a second and its fill follows within a quarter of a second, so one run in two caught it between the two ("fill 22.4% for a value at 67.3%") on the same commit that had just passed. The rule was right and the instant was wrong: a slider that is off is looked at again 300 ms later, and only then reported.

## A design that reads well and a board that says no (2026-10-05, effect detail on the Pi 4)

- **Measure the alternative before building it.** A reviewer's design for the cap was two passes: filter small, then mix with the untouched clip at full size, so that Amount 0 would be exactly the clip. It reads better than what was built. The numbers of the first run already said a pass over a 1080p picture costs this board 6 to 9 ms; a hand-made text given to the player through its socket showed it in ten minutes: the cheapest filter dropped 2.6 frames a second that way. What we do now: when a design's cost can be tried with a text file and the player's socket, try it on the board first; no engine code is needed for that.
- **The player turns a picture before a user shader's NATIVE hook.** I believed the hook met the clip as it is stored and wrote a text that was told which side was the shorter one from the clip's stored size. A CI probe (a hook that paints by `HOOKED_size.x > HOOKED_size.y`) said otherwise for a clip turned by a quarter, and the "softer" picture of my own test had been a picture capped on the wrong side all along (34 lines where 60 were meant), inside the tolerance. What we do now: a text that depends on a fact about the player carries a test of that fact, and where the arithmetic can be made not to depend on it (here: one expression for both ways), it is.
- **A probe at NATIVE speaks the clip's colours.** My first probe returned green for "right" and red for "wrong" and judged the screenshot by its green channel: over a video those are a brightness and two colour differences, and every point read as wrong. Return a brightness and one half for the two colour differences.
- **A tolerance wide enough for "softer" hides a wrong size.** See above: mean 5.3 of 255 under a limit of 6. The check that found the real size was the one that compared the code's size with the player's, pixel for pixel. Prefer a check of the quantity itself over a check of its symptom.
- **A skipped hook is not a free hook.** With `//!WHEN 0` the player draws no pass for the filter, and still merges the planes and converts the colours in passes of their own because a NATIVE hook exists: 22.6 ms against 13.1 for the clip alone. "Leaves it out" is true of the filter and not of the cost.
- **`pgrep -f` in a waiting loop matches the loop.** A shell told to wait `while pgrep -f "m.py run"` and then run `m.py run` has that string in its own command line and waits for ever. Wait on the process number (`kill -0`).
- **`git archive` writes a plain tar with no folder in front.** A deploy line written from memory piped it into `tar -xzf`; it needs `--format=tar.gz --prefix=nxlx-src/`, or nothing unpacks, or the tree lands loose in `/tmp`. The line that was run is in HANDOFF ("Deploy master").
- **Two of my three "fixes" had a defect of their own, and a reviewer found both by asking what else moves the same state.** The guard's new rule was right for the case I had met (a loop sets the count to 0) and wrong for every other fall; the error's new flag was right when the state is polled and wrong when it is not. What we do now: for a fix, write down the other ways the same variable can change (who else sets it, what else can make the number fall) and test one of them, not only the case that prompted the fix.
- **A flag beside a value goes stale; a mark on the value cannot.** `_waiting = True` described `self.error` and survived its replacement. Keeping the error object itself as the mark (`self.error is self._waiting`) makes "this one, and no other" something the language checks.
- **The box knows a change before its answer is back (2026-10-05).** A handler changes the settings, saves them, then answers; a second request in that gap already sees the change. A browser test that waits by asking the box goes on while the page is still about to draw the answer, and its next action lands on a card that is then rebuilt. Wait for what the panel shows (mark the card's top line, wait for a new one). The request log in the CI job showed it: the Save was answered 400, 35 ms after the answer before it.
- **Typing in Playwright is two steps (2026-10-05).** `fill` chooses the field and then inserts the text. A card rebuilt between the two loses the text without any error. A card that rebuilds itself must give the cursor back (`keepCursor` in `app.js`), or not rebuild while a field in it has the cursor (the Shaders page's `held`); a person on a slow link meets the same thing.
- **Force the window, then say "demonstrated" (2026-10-05).** Five races were each made to happen every time by holding one side still at the suspected moment: a delayed answer, a held status check, a write that waits for the other side's close, a call that takes longer, a save that waits for the other change. A test that fails every time with the fix taken out, with the message CI printed, is the proof; a loop that happens to pass is not.
- **A dropped event leaves state behind (2026-10-05).** The MIDI hub rightly drops what arrives while MIDI is off, and so never heard a button's release: the button stayed "held" and its next press did nothing. Whatever stops listening must also forget what it was in the middle of.
- **Read before giving up on a failed write (2026-10-05).** A server that refuses by answering and closing without reading can beat the client's write; the write then fails although the answer is waiting. The client reported "not running" for "not allowed".
- **Read, change and write under one lock (2026-10-05).** The shader settings were changed in two steps and only the second held the lock; a change made in between was overwritten and then kept. Two quick choices could leave the earlier one standing.
- **"Cancelled" has an author: read the job's annotation (2026-10-05).** `gh api repos/<owner>/<repo>/check-runs/<job id>/annotations` says what ended a job: "The strategy configuration was canceled because test._3_9 failed" (a matrix stops its other jobs when one fails) or "The run was canceled by @name" (a person, or a session using that person's `gh`). Of 60 runs with a cancelled test job in two days, 23 were the first kind; every other one that was read (11 runs) was cancelled by hand, and none was a runner problem or a time limit. A cancelled job keeps no log, so the matrix now runs with `fail-fast: false`.
- **`gh run list` shows a rerun run as it ended (2026-10-05).** A failure that was rerun to green is only in the earlier attempt (`actions/runs/<id>/attempts/<n>/jobs`). Count those, or the failures that come and go look rarer than they are.
- **Every push starts each workflow twice, and the queue is short (2026-10-05).** A push to a branch with an open pull request starts a `push` run and a `pull_request` run of every workflow; with three sessions pushing, runs waited 30 minutes and more for a runner. Cancel the runs of a commit that a newer one has replaced.
- **A job with no time limit can wait on a download for six hours (2026-10-05).** A `panel-ui` job spent twenty minutes installing packages that usually take 45 seconds: the runner's mirror gave about 50 kB a second. Give every job `timeout-minutes` and every step that downloads a shorter one of its own; a step that runs out of time fails with what it had printed.
- **Putting text back by a field's id is not putting it back into the same field (2026-10-05).** `keepCursor` gave a rebuilt field the old one's text because it had the same id; the field had meanwhile become another surface's name. Restore what was typed only when the card built the new field from the same content as the old one, and keep state that outlives a redraw in one place, emptied before the redraw that should show it empty. Found by the independent review, not by me.
- **A test made weaker to stop it failing has to be attacked before it is believed (2026-10-05).** My repaired stagger test passed two wrong monitors, and the check I proposed in its place would have failed the right one. Write down the wrong implementations a test must catch and run it against each.
- **A third kind of "cancelled": no runner (2026-10-05).** "The job was not acquired by Runner of type hosted even after multiple attempts" is GitHub giving up on a queued job after about half an hour. The run reads as failed; nothing ran.
- **"Looks the same" can be shown without a browser, by substitution (2026-10-05).** The Signal block was rewritten to read about a hundred values through `var(--tk-..., fallback)`. The dev Mac has no browser test, so a throwaway script put every fallback back, undid the `calc()` forms, and compared the result line by line with master's block: 371 lines, none different, plus a short list of added rules that are 0 without their token. Do the same for any refactor that moves literals behind variables, and keep a unit test that the fallbacks equal the defaults in the code that writes them.
- **A request body parsed as JSON has already lost a repeated key (2026-10-05).** `json.loads` keeps the last of two keys with the same name and says nothing, so a route that takes a file as the JSON body cannot refuse "the id twice". The theme file travels as text inside the request (`{"file": "..."}`) and is parsed once, strictly, by the code that validates it; the settings import reads raw bytes for the same reason.
- **A primary action and a chosen state shared one class (2026-10-05).** `.btn.on` was both "Save" and "this bank is open", so "primary actions outlined" could not be said in CSS without also un-filling what is chosen. The 29 buttons whose class is written as a constant got a second class, `pri`, which draws nothing by itself. When one class means two things, a token finds out.
- **A test's list of provoked answers is part of the test (2026-10-05).** The browser test counts console errors and has a list of HTTP statuses it causes on purpose; a new refusal with a new status (422 for a theme the box will not take) has to be added there, with the reason, or the test fails on its own subject.
- **A rule enforced at one door and not at the next is not enforced (2026-10-05).** Themes were refused under 4.5 to 1, and the accent, which replaces a theme's accent, went in through `POST /api/theme` with only "is it a colour". The function that computes the pairings already took an accent; no caller passed one, and a test asserted the faint case returned 200. When a check is added, list every way the same value reaches the page and call the check from each; an unused parameter of a checking function is a door left open.
- **"Skipped, never fatal" still has to be said somewhere (2026-10-05).** A damaged add-on theme was skipped in silence, so the owner would see a look missing with no word why. What is skipped gets one log line and a line on the page of whoever can fix it.
- **An answer that says "off" is still a 200, and it has holes where the page expects things (2026-10-05).** `GET /api/shaders` answers while the module is off, with no shader and no set, and the box is off from the first moment of the switch's request, before the panel has that request's answer. The Shaders page drew it and read the time of a set that was not there (`Cannot read properties of null (reading 'dwell')`, once in CI). A page that draws from a GET checks first that the answer is one it can draw (`loaded()`), and shows nothing otherwise. The error message named a field, and the first guess at the line (`data.config.dwell`) was wrong: `config` is always sent, it was `e.dwell` of the set being edited. Find which read it is from what the box sends, not from the nearest matching name.
- **A wait that is already true does not wait (2026-10-05).** The screenshot step tapped the Room tab and waited for the first wall, but a presenter lands on Room, so the wall was there before the tap's redraw; the fold opened next was closed by that redraw. When a tap redraws a screen, wait for the new screen (mark the old one), not for something the old one also had.
- **A set-up assertion that depends on timing is itself a flaky test (2026-10-05).** A projector test took the entry out of the settings and then asserted "the worker is still there", which was true only until the worker woke 50 ms later, saw the entry gone and left by itself. If a test needs a thread to be at a certain place, hold it there (a gate in its way out, waited for with a deadline) and assert it arrived; and give the other order a test of its own.
- An answer of 200 is not an answer that can be drawn: the box answers for a module that is off, with the lists empty. Each page decides with one function whether an answer is complete before reading into it (`loaded()` for shaders), and a browser step switches the module off under the open page.
- **A fake made of plain bytes hides what the real buffer does.** The NDI frame copy passed every test with frames made of `bytes` and would have failed on the first padded frame from the library: a view of a ctypes array has the format "<B", and a slice of it cannot be assigned into a byte buffer. When a seam stands in for memory from C, give one test the real kind of object (a ctypes buffer), even where the library itself cannot be loaded.
